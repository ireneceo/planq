# 파일·문서 연결 점검 — 옮기면 끊기나 · 어디에 연결됐는지 보이나 (2026-11-25)

> Irene: *"파일 위치를 이동하거나 해도 연결해둔 문서에서 끊기지 않게 하거나 꼭 구조상 끊어야 하면 알려줘야 할 것 같아. 그리고 파일이나 문서들이 서로 어디에 연결되어 있는지 제대로 다 알게 통합적인 UI가 되고 있나 궁금해."*
> [Opus] 코드 읽기 + dev DB 집계. 코드 변경 0. Fable 안 씀(조사) — 고치는 설계는 권한·삭제를 건드려 Fable 대상.

## 1. 결론 한 줄
**옮기기(폴더 이동)로는 끊기지 않는다. 끊기는 것은 «지우기»와 «공개 범위 좁히기» 이고, 그때 아무 말도 하지 않는다.**
연결을 한눈에 보는 화면은 **없다** — 파일 쪽엔 «출처» 한 줄(글자, 누를 수 없음), 문서 쪽엔 첨부 목록만. 혼란 쪽에 가깝다.

## 2. 연결이 걸리는 방식 (실제 코드)
| 연결 | 무엇으로 가리키나 | 폴더 이동 | 지우기 | 범위 좁히기(L1·다른 프로젝트) |
|---|---|---|---|---|
| 문서 첨부 `post_attachments` | 파일 번호 | ✅ 유지 | ⚠️ 목록에 이름은 남고 열면 없음(추정 — `postSerialize` 가 지운 파일을 안 거름) | ⚠️ 읽는 사람이 못 열 수 있음, 말 없음 |
| 문서 본문 그림 | 저장 파일 이름(`/api/posts/editor-image/<이름>`) | ✅ 유지(경로 안 바뀜) | ⚠️ 그림 자리가 빈다 — Q file 에서 지울 때 «문서에 쓰임» 안내 없음 | ⚠️ 같음 |
| 업무·채팅·일정·메일 첨부 | 파일 번호(업무는 자기 사본 행) | ✅ 유지 | ⚠️ 같음 | ⚠️ 같음 |
| Drive 사본 | `gdrive_mirror_id` | ✅ Drive 에서도 같은 자리로 옮김(`folder_actions.mirrorMove`) | 휴지통과 같이 거둠 | — |

- 폴더 이동 = `files.folder_id` 한 칸만 바뀐다(`services/actions/folder_actions.moveFiles`). 다른 프로젝트 폴더로는 못 옮긴다(가시성 확대라 막음).
- 지우기 = `trashFile`(휴지통, 복구 가능). 복구하면 연결은 다시 살아난다(연결 행은 지우지 않음).
- 삭제 라우트·확인창은 **그 파일이 어디에 붙어 있는지 보지 않는다.**
- 문서 첨부 응답은 파일의 지금 공개 범위를 보는 사람 기준으로 다시 거르지 않는다 — 붙인 뒤 «나만 보기» 로 바뀐 파일은 **이름은 보이고 열면 막힘**(공유·참조 규칙 5 «보여줄 때 보는 사람 기준» 과 어긋남. 코드 읽기, 실호출 확인 못 함).

dev 실측(지금 데이터): 살아 있는 문서 첨부 7건 · 지운 파일을 가리키는 연결 0 · 두 곳 이상에 쓰인 파일 10개. dev 데이터가 적어 «이미 끊긴 것» 숫자는 운영에서 따로 세야 한다(읽기 전용).

## 3. «어디에 연결됐나» 화면 — 지금 있는 것
- Q file 목록: 출처 칩(채팅·업무·회의·문서·메일) — **종류만**, 어느 문서·업무인지는 미리보기의 «출처» 글자 한 줄(처음 하나, 누를 수 없음).
- 문서: 첨부 목록 · 연결 문서(`link_documents`) · 업무 칩(`linked_tasks`) · 프로젝트 «연결됨»(project_refs) — 문서 쪽이 그나마 낫다.
- 없는 것: 파일 하나가 **어느 문서·업무·채팅·일정에 다 쓰이는지** 한 목록 · 거기서 바로 열기 · 지우기·범위 바꾸기 전에 그 목록을 보여 주는 확인.

## 4. 권고 (Fable 설계 1회 뒤 구현)
1. **사용처 한 함수** `services/fileUsage` — 파일 번호 → 문서 첨부·본문 그림·업무·채팅·일정·메일 목록(보는 사람이 볼 수 있는 것만 제목, 못 보는 것은 «볼 수 없는 곳 N곳» 숫자만).
2. **파일 상세 «연결된 곳» 칸** — 위 목록, 누르면 그 문서·업무가 열림. 출처 한 줄을 대신한다.
3. **지우기 확인창** — 쓰이는 곳이 있으면 «문서 2곳·업무 1곳에서 이 파일이 빠집니다(휴지통에서 복구하면 돌아옴)» 를 적는다. 여러 개 지우기도 같이.
4. **범위 좁히기 확인** — «이 파일이 붙은 문서를 보는 사람 중 일부가 못 열게 됩니다» + 곳 목록.
5. **지운 파일이 붙은 자리** — 문서·업무 첨부 목록에서 «휴지통에 있음» 으로 보이게(누르면 404 대신 이유). 본문 그림 자리도 같은 문구.
6. 문서 첨부 응답을 보는 사람 기준으로 다시 거른다(규칙 5).

끊지 않을 방법이 없는 경우 = 지우기·범위 좁히기뿐이고, 둘 다 «알려 주고 묻는다» 로 충분하다(연결을 막아 지우지 못하게 하는 것은 권하지 않음 — 정리를 못 하게 된다).
