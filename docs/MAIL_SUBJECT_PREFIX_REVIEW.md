# 고객에게 가는 메일 제목 접두어 검토 — Fable 판정 대기 (2026-10-21)

> Irene 원문: *"워크스페이스 이메일 발신자로 가는 메일에는 제목부터 굳이 [PlanQ] 이런거 넣지 말자. 고객사들에게 안좋은 것 같아. 검토 좀 해줘. 이건 fable 이 검토해. 상황파악 제대로 해야 하거든."*
> 상태: **사실 조사 끝 · 구현 0** — Fable 한도(429)로 판정을 못 받아 설계가 막혔다(공용 기준 5절). 판정을 받으면 «판정» 절을 채우고 구현한다.

## 1. 사실 (운영 email_logs 지난 30일 · 읽기 전용 실측 2026-10-21)

- **리터럴 «[PlanQ]» 제목은 이미 안 나간다** — 30일간 1건(09-23 체험 만료, 규칙 바뀌기 직전). 2026-09-23(#425) 부터 플랫폼 메일은 접두어 없음.
- 지금 규칙 = `services/emailService.js subjectPrefix()` 한 함수: 워크스페이스 맥락 메일은 제목 앞 **«[워크스페이스명]»**, 플랫폼 메일은 없음.
- 보내는 주소는 늘 `noreply@planq.kr`. **표시 이름만** 바뀐다 — `fromName` 이 있으면 그 이름, 없으면 «PlanQ».
  워크스페이스 설정 > 메일의 «보내는 사람 이름»(`businesses.mail_from_name`)·회신 주소(`mail_reply_to`).

→ **워크스페이스 이름으로 보낸 메일은 받은편지함에 «워프로랩 | [워프로랩] 청구서 — …» 처럼 이름이 두 번 보인다** — 09-23 에 PlanQ 가 겪은 «PlanQ | [PlanQ] …» 와 같은 모양.

- 본문: 모든 메일 맨 위가 **PlanQ 로고 헤더**(planq.kr 링크). 워크스페이스 메일 푸터는 «<워크스페이스> 에서 보낸 메일입니다» 크게 + «PlanQ 로 발송됨 · planq.kr» 작게.
- 내부 멤버 알림(`notify:*`, 표시 이름 PlanQ, `[워프로랩] Q Task · 새 업무 배정 · …`)은 고객사에 가지 않는다. 여러 워크스페이스를 쓰는 멤버에게 [ws] 는 어느 곳 일인지 알려 준다.

## 2. Fable 이 정할 것

1. «[PlanQ] 이런거» 가 실제로 가리키는 것 — 운영엔 [PlanQ] 가 이미 없다. «[워크스페이스명]» 대괄호 꼬리표 전반으로 읽는가.
2. 고객행 메일 제목 규칙 — (a) 표시 이름이 워크스페이스인 메일만 접두어 빼기 (b) 고객행 메일 전부 빼고 표시 이름을 전부 워크스페이스로 맞추기(서명 요청·공유·초대·증빙도 같은 사슬) (c) 기타. 내부 멤버 알림의 [ws] 유지/제거.
3. 접두어를 빼면 «누가 보냈나» 가 사라지는 메일(표시 이름 PlanQ)의 처리.
4. 워크스페이스명이 없을 때의 'PlanQ' 폴백.
5. 본문 PlanQ 로고 헤더를 이번 범위에 넣나(Irene «제목부터»).
6. 되돌리기 어려운 점 — 스팸 판정(표시 이름 ≠ 발신 도메인)·발신 평판·회신.
