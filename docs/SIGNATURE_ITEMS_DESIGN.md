## 1. 바꾸는 원칙
1. **서명 요청은 «서명 자리» 가 있어야 보낸다.** 자리가 없으면 보내기를 막고 이유를 말한다(문서 끝 별도 영역으로 몰래 붙이지 않는다). 확인 요청(가벼운 확인)은 그대로.
2. **한 서명자 = 여러 항목.** 사인(필수) · 회사 스탬프(문서마다 필수/선택) · 서명일(자동) · 이름(자동). 항목마다 문서의 원하는 자리에 둔다.
3. **편집 밖에서 끝난다.** 문서 보기 → [서명 요청] 한 곳에서 «자리 → 사람 → 보내기» 를 화면이 순서대로 안내한다. 편집기는 «정확한 자리에 직접 넣고 싶을 때» 만.
4. **손으로 적은 자리는 찾아서 바꿔 준다.** «서명: ____» · «서명일: ____» · «회사 스탬프:»/«도장:»/«(인)» 줄을 그 자리의 항목으로.
5. **증빙은 한 벌.** 서명본(문서·공유 링크·서명 화면·PDF)은 지금처럼 `signedDocument` 한 함수가 조립한다. 스탬프도 같은 길로.

## 3. 데이터

### 3-1. 문서 안 항목 — 기존 노드를 넓힌다(새 노드 X)
`signatureField` 에 속성 `item` 추가: `'sign'`(기본·기존) | `'date'` | `'stamp'` | `'name'`, 그리고 `required`(스탬프만 의미).
- 저장 형태 `<div data-signature-field data-slot data-party data-label data-item data-required>`.
- **기존 문서·기존 요청은 `item` 이 없다 = `sign`** → 무변경으로 지금처럼 보인다.
- 서명자 정보(이름표·쪽)는 **그 번호의 `sign` 항목**이 정본. date·stamp·name 항목은 번호만 갖는다(값을 복사해 두면 갈라진다).
- 읽는 공식은 `utils/signatureFields.ts` 한 곳(편집기·요청 창·서명 화면) + 서버 `signedDocument` (저장된 HTML 속성) — 지금 구조 그대로.

### 3-2. 서명 요청 — 열 3개
| 열 | 뜻 |
|---|---|
| `required_items JSON` | 요청 시점에 문서에서 읽은 그 번호의 항목 `["sign","date","stamp:required"]` — 고정본과 함께 동결(서명 화면이 무엇을 받을지) |
| `stamp_image_b64 TEXT(long)` | 스탬프 이미지(dataURL, png/jpeg, 서버에서 길이·형식 검사 — 사인과 같은 규칙) |
| `stamp_hash VARCHAR(64)` | 스탬프 SHA-256 — 증명서 장에 싣는다 |
- 운영 적용: `scripts/migrate-signature-items.js`(멱등, 배포 슬롯, 코드 전). 롤백: 코드만(열은 남아도 무해).

### 3-3. 서명본 조립
`signedDocument.injectSignatures` 가 `data-item` 으로 가른다 — sign: 사인 이미지 · date: `서명 시각`(문서 언어 형식, 예 «2026년 10월 6일») · stamp: 스탬프 이미지 · name: 서명자 이름. 서명 전에는 각 자리가 «서명 전» 빈칸. 증명서 장에 스탬프 해시·업로드 시각 추가.

## 4. 서버
- `POST /api/posts/:id/signatures`: kind=sign 이면 **sign 항목 ≥ 1, 서명자마다 sign 항목 1** 이어야(아니면 400 `signature_fields_required`) — 화면만 막으면 다른 문(에이전트 도구 등)이 우회한다.
- `POST /api/sign/:token/sign` · `POST /api/signatures/:id/sign-internal`: `stamp_image_b64` 받음. required_items 에 `stamp:required` 면 필수(400 `stamp_required`). 크기 5MB·형식 png/jpeg·dataURL 정규식(지금 사인과 같은 검사).
- 손 자리 → 항목 바꾸기는 **화면이 문서를 저장**(`PUT /api/posts/:id`, base_updated_at 409 그대로) — 새 라우트 없음.

## 9. Irene 결정 (2026-10-05) — **한 패턴으로 단순화** · 이 절이 위 설명보다 우선한다
> *"왜 필수를 해? 사인이 그냥 직접하는 거 또는 이미지 추가가 있으면 되고 그게 어디든 위치를 지정하면 되는거지.
> 서명일은 워크스페이스 날짜 표기 기준으로 해. 시간 필요없어. 서명자 이름도 날짜처럼 어디에 추가하게 하면 되잖아.
> 같은 맥락으로 같은 패턴으로 만들면 되는 거 아니야?"*

- **항목 = 문서에 놓는 칸 하나 + 서명자 번호.** 종류는 셋뿐 — `sign`(서명) · `date`(서명일) · `name`(이름). «회사 스탬프» 라는 종류는 **없다**.
- **서명 칸은 «그리기 또는 이미지 올리기»** — 사인이든 회사 스탬프든 서명자가 고른다. 한 서명자에게 서명 칸을 **여러 개** 둘 수 있다(사인 칸 + 스탬프용 칸).
- **필수/선택 없음.** 문서에 놓인 그 서명자의 서명 칸은 전부 채운다(그리기 또는 이미지). `required` 속성 없음.
- **서명일** = 워크스페이스 날짜 표기(`businesses` 날짜 형식 설정) · **날짜만**(시각 없음 — 시각은 증명서 장에).
- **이름** = 서명 요청 때 정한 서명자 이름.
- **재사용 저장 안 함**(매번 올린다).
- 데이터: 열 `stamp_image_b64`·`stamp_hash` 대신 **`item_images JSON`** `[{index, mode:'draw'|'image', b64, sha256}]` — 그 서명자의 서명 칸 순서대로.
  기존 `signature_image_b64` 는 첫 칸 값으로 계속 채운다(옛 화면·옛 요청 호환). `required_items` 는 «그 서명자의 서명 칸 개수 + date/name 유무» 로.
- 손 자리 찾기: «서명:» → 서명 칸 · «회사 스탬프:/도장:/(인)» → **서명 칸**(같은 사람의 두 번째) · «서명일:» → 날짜 칸 · «성명:/대표자 이름 줄» 은 바꾸지 않는다(이미 글자로 이름이 있다).
- 서명 화면: «내 칸 N개» 를 차례로 — 칸마다 [그리기 | 이미지 올리기] 같은 컨트롤 하나.
