## Fable 판정 (2026-11-19) — VERDICT: BUILD-NOW (a·d·f) · 고정 출구 IP 를 먼저 정한 뒤 공개 · 중계는 같이 간다
1. **상대 서버를 사람 손 없이 열게 하는 방법은 없다** — 방화벽 허용을 외부에서 요청·반영하는 표준이 없다. 자동화되는 것은 «막힘 감지 → 무엇을 요청할지 다 써 주기 → 열리면 알아서 연결» 까지.
2. 조각별
   | 조각 | 판정 | 이유 |
   |---|---|---|
   | a. 요청서(IP·포트·호스트·계정, ko/en, 복사 + 메일 앱으로 열기) | 지금 | 가장 싸고 모든 나라에 통함 |
   | d. 업체별 관리 화면 안내 | 지금, 작게 | 실제 확인한 업체 2~3곳만 · 추측 경로 금지 |
   | f. [다시 확인] + 열리면 알림 | 지금 | 하루 재확인은 이미 있음 — 버튼·알림만 |
   | e. 공개 IP 목록 페이지 | 나중 | 4번 뒤 · 무인증 표면이라 게이트 대상 |
   | b. PlanQ 가 대신 발송 | 안 함 | 고객 본인 주소에서 가야 관리자가 믿음 · 사칭·발송 평판 위험 |
   | c. 관리자 연락처 자동 찾기·발송 | 안 함 | WHOIS/abuse 는 신고 창구 — 사칭 메일과 같음 |
3. **중계와 보완 관계** — 순서: 직접 → (그 나라 중계 있으면) 중계 → 없거나 실패면 요청서. 중계는 고객이 몰린 나라(지금 한국)만, 요청서는 그 밖 모든 나라의 기본 길. 중계로 붙은 계정에는 요청서를 강요하지 않음.
4. **고정 IP 먼저** — 공개 IP 는 고객 방화벽에 박혀 우리가 못 고친다. 공개 집합 = 운영 출구 IP 하나(개발·중계 IP 제외). 서버를 옮겨도 따라가는 IP 인지 확인이 선행. 운영 IPv6 가 켜져 있으면 메일 연결 IPv4 고정 또는 v6 도 공개. 요청서에 «바뀔 수 있음 · 최신 목록 주소».
5. 놓친 것 — IP 공개 위험은 낮음(DNS 로 이미 보임 · 출구=웹 IP 인지 확인) · **사칭 위험이 핵심**(요청서에 «PlanQ 는 비밀번호를 묻지 않는다» · 실제 쓰는 포트만) · **로그인 단계 «해외 로그인 차단»(네이버·다음·하이웍스)은 별개** — 방화벽 요청서가 아니라 본인/관리자 설정 안내, 이 분류 기준은 설계 판정 따로 · 요청서는 로그인 사용자에게만.

## 최소 구현 순서
1. 운영 출구 IP 실측·고정 확인(v4/v6) — 값은 서버 설정 한 곳 → API(화면 하드코딩 금지)
2. `*_unreachable` 안내 → [무엇이 막혔나 한 줄] + [요청서 보기](IP·포트·호스트·계정 · ko/en · [복사]·[메일 앱으로 열기])
3. [다시 확인](연타 제한) + 하루 재확인 성공 시 알림 1회(«이제 직접 연결됩니다»)
4. 실측 확인한 업체 2~3곳 관리 화면 안내
5. (나중) 공개 IP 페이지 · 로그인 차단 분류
