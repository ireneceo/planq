# UI/UX 검증 체계 — 사용자가 먼저 만나지 않게

> Irene 2026-10-07: *"모든 ui/ux 체크를 fable이 제대로 할까? 기능 안되는 거 없는지 통일된 곳 없는지 어디서 어떻게
> 어떤 기준으로 검증하면 사용자 입장에서 문제를 마주칠 일이 없을지 제대로 파악해서 완벽한 검증 좀 해줘.
> 자꾸 모바일에서도 깨지고 기능이 작동 안하는 것도 나오고. 너무 심각해."*

## 1. 답 — Fable 이 하는 일이 아니다

Fable 은 **바뀐 코드(diff) 하나**를 읽고 판단하는 검토자다. 화면 수백 개 × 폭 3가지 × 역할 × 연 상태를
매번 눈으로 볼 수 없고, 봐도 «다른 화면이 같이 깨졌는지» 는 diff 에 안 보인다. 그래서 CLAUDE.md 가 UI 를
**F=1(기계가 참/거짓을 가르는 것)** 로 분류해 Fable 에 올리지 않는다 — 맞는 분류다.

UI/UX 를 지키는 것은 **기계 검사가 매일 전부 도는 것**과 **그 결과를 누군가 반드시 읽는 것** 둘이다.
Fable 은 되돌릴 수 없는 것(권한·결제·공개 링크·외부 발송)과 «무엇을 검사해야 하는지부터 설계해야 하는 것» 에만 쓴다.

## 3. 무엇을 · 어디서 · 어떤 기준으로

### 3-1. 축 (빠진 칸이 곧 구멍이다)
화면(목록·**상세**·연 창) × 폭(폰 390/360 · 태블릿 820/1024 · PC 1440 · **앱 흉내** 폰/아이패드) × 역할(owner · **고객**) × 상태(빈 데이터 · 긴 제목 · 키보드 올라옴)

### 3-2. 기준 (기계가 가르는 것만 실패로 센다)
| 무엇 | 판정 | 검사 |

| 화면이 깨짐 | 화면 밖 삐져나감 · 누를 것끼리 겹침 · 그려지지 않는 버튼 · 가로 넘침 | `screenbreak` `patrol` |
| 연 창이 깨짐 | 창이 화면 밖 · 위/아래가 헤더 등에 가려짐 · 내용 잘림 · 폰 패널 빈자리 | `patrol`(연 창 판정) `mobilepanels` `modaltop` |
| 모바일 입력 | 키보드 위에 보임 · 헤더 밑에 안 숨음 · 내리면 원래대로 · 입력 중 캐럿 보임 · 한글 조합 | `mobile` `mobilesweep` `caret` `hangulime` |

## 4. 검사기 자체를 믿는 법
- **양성 대조군**: 결함을 일부러 되살렸을 때 빨개지는지(`PATROL_CONTROL=1` 등). 안 빨개지면 초록은 거짓이다.
- **⚪ 미측정은 통과가 아니다**(run.js 가 실패로 센다). 순찰도 «연 창 0개 잼» · «상세 대상 못 고름» 을 미측정으로 낸다.
- **잔여 청소는 판정 항목이다** — 카나리가 남긴 업무·알림이 다음 순찰의 거짓 실패가 된다(10/6 «찾을 수 없음» 10건 중 다수가 지워진 카나리 업무 알림).
