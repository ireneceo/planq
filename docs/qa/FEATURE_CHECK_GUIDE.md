# 메뉴별 기능 점검 안내 — 유료화 디테일 잡기 (2026-11-25)

> Irene 2026-11-25: *"유료화 하며 업그레이드 하는 기능들 소소한 디테일 계속 잡아야 해. 모든 기능 체크하게 기능파악에 맞게 안내 좀 해줄래? 메뉴마다 기능들 제대로 파악할거야."*
> 순서 = 사이드바 순서(`dev-frontend/src/config/navMenus.ts`). 한도 정본 `dev-backend/config/plans.js` · 판정 `services/plan.js can()`.
> 상황판 «확인할 곳» 버튼은 각 줄 끝 `[as=역할 ws=번호]` 계정으로 로그인해서 연다.

## 0. 두 워크스페이스로 비교한다

| | ws 6 «PlanQ 테스트 워크스페이스» | ws 7 «브랜드 파트너스» |
|---|---|---|
| 플랜 | **Pro** (정상 결제 · 다 열림) | **무료** (11-25 옛 체험 잠금 → 무료로 내려옴) |
| 쓰는 목적 | 기능이 «제대로 되는지» | 한도에 «걸리는 모습이 맞는지» |
| 지금 사용량 (11-25 API 실측) | — | 멤버 **3 / 한도 2**(무료 1 + 추가분) · 고객 2/3 · 프로젝트 **4/2** · 대화방 **7/5** · 저장 0/500MB · Cue 0/20 · 녹음 0/60분 · 설문 0/10 |

★ ws 7 은 멤버·프로젝트·대화방이 **이미 한도를 넘은 상태**다(옛 데이터). 그래서 «새로 만들기» 는 첫 번째부터 막혀야 맞다 —
«한도를 넘었을 때 기존 것은 그대로 쓰이고 새로 만들기만 막힌다» 가 지금 1단계 정책이다(읽기 전용 전환은 2단계 · `docs/FREE_PLAN_PROPOSAL_2026-11-25.md` §8).

한도에 걸리면 뜨는 창은 하나 — `LimitReachedDialog`(무엇이 몇/몇인지 + 애드온·업그레이드 버튼). **창 없이 아무 일도 안 일어나면 그게 결함**이다.

## 1. 점검할 때 매번 볼 다섯 가지
1. **만들기·고치기·지우기** — 저장 뒤 새로고침해도 그대로인가
2. **권한** — 멤버(`as=member`)·고객(`as=client`)에게 안 보일 것이 안 보이는가
3. **한도** — ws 7 에서 막히는 순간 창이 뜨고 문구·숫자가 맞는가(영어 화면도)
4. **빈 상태·오류 문구** — 아무것도 없을 때 안내가 있는가
5. **폰 폭** — 같은 화면을 폰에서 한 번

## 3. 알고 보면 좋은 것 (11-25 조사)
- 중간 플랜(Starter·Basic) 시험 워크스페이스는 없다 — 무료(ws7)·Pro(ws6) 두 개로 비교한다.
- ws6 은 Pro 결제 중인데 옛 체험 끝 날짜(2026-05-19)가 기록에 남아 있다 — 화면에 «체험 끝남» 류 문구가 보이면 결함.
- ws7 API 는 «선결제 1개월 보너스» 를 `available:true` 로 준다 — 무료 화면 결제 창에서는 안 보이게 한 것이 정책(1단계 기록). 보이면 결함.
- 점검하면서 데이터를 만들면 이름 앞에 `[확인용]` — 7일 뒤 정리된다.
