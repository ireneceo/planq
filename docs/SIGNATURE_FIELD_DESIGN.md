# 서명란 · 서명본 PDF · 우리 측 서명 — 설계안 (2026-09-22, 승인 대기)

> Irene: *"문서에 서명이 어떻게 나오는지 알 수 없어서 서명란을 입력하게 된다고 했는데"*

## 0. 지금 상태 (조사 결과)
- 서명은 `signature_requests.signature_image_b64` 에 **따로 저장만** 된다. 문서 본문·공유 링크·PDF 어디에도 안 나온다.
- 서명자는 문서 아래 별도 칸에 그린다 — **어디에 들어가는지 모른다.**
- 템플릿(견적·NDA·계약)의 «서명/날인» 칸은 항상 `—` (장식). `footer.signature_zone` 설정은 읽는 코드가 없다.
- 우리(보내는 쪽) 서명 단계가 없다. 완료 화면 문구는 «양측 서명» 을 말한다.
- 채팅 카드에는 서명자가 여럿이어도 **첫 서명자의 링크 하나**만 실린다.
- ✅ 이미 고침(2026-09-22): 앱 안 서명 진행 표의 서명 썸네일.

## 1. 서명란 블록 (B)
**문서 편집기에 «서명란» 블록을 넣는다.** 표 칸 안에도 넣을 수 있다.

```
┌ 서명란 ────────────────────┐
│ 갑 (우리)  ·  (서명 전)      │   ← 편집 중: 이름표만 보이는 빈 칸
└────────────────────────────┘
┌ 서명란 ────────────────────┐
│ [서명 이미지]                │   ← 서명 후: 이미지 + 이름 + 일시 + «전자서명 인증»
│ 김도윤 · 2026-09-22 14:03    │
└────────────────────────────┘
```

- 블록 속성: `slot`(서명자 칸 번호 1·2…) · `label`(예: 갑·을, 발주사·수행사) · `party`(`us` | `them`).
- **서명 요청 창**에서 서명자를 칸에 짝짓는다 — «을(고객) ← 김도윤 doyun@…».
  서명란이 **없는** 문서는 문서 끝에 서명 영역을 자동으로 붙인다(서명자 수만큼).
- **템플릿**의 `—` 칸을 서명란 블록으로 바꾼다(견적·NDA·계약·용역). 이미 만든 문서는 그대로 둔다.
- **서명하는 화면**: 문서에서 자기 칸을 강조하고 «여기에 서명이 들어갑니다» 를 띄운다. 그리기 칸은 지금처럼 아래.

## 2. 서명본 = 고정된 문서 + 서명 (C)
- 서명 요청 때 이미 문서 내용이 고정 저장된다(`frozen content`). **서명본은 그 고정본에 서명을 끼운 것**이다 —
  요청 뒤에 원본을 고쳐도 서명본은 바뀌지 않는다(계약서의 원칙).
- 보여 주는 곳 3곳이 같은 그리기를 쓴다: 앱 안 문서 · 공유 링크 · PDF.
- **서명본 PDF** 마지막 장에 **서명 증명서**:
  문서 제목 · 고정본 지문(SHA-256) · 서명자별 이름·이메일·본인 확인(인증번호) 시각·서명 시각·IP.
- 문서 화면 ⋯ 메뉴에 «서명본 PDF 받기» (모든 칸이 서명됐을 때만. 진행 중엔 «진행 중 사본»).

## 3. 우리 측 서명 (D)
- 서명란 `party: us` 칸은 **보내는 쪽 멤버가 앱 안에서** 서명한다(로그인 + 동의 체크 + 그리기. 인증번호 대신 로그인이 본인 확인).
- 서명 순서 선택: **동시**(기본) · **우리 먼저**(우리 서명이 끝나야 상대에게 링크 발송) · **상대 먼저**.
- 완료 = 모든 칸 서명. «양측 서명 완료» 문구는 이때만 쓴다.

## 4. 채팅 카드 (E)
- 여러 사람이 보는 방에 **서명자별 링크(=그 사람 열쇠)를 올리지 않는다.**
- 카드에는 문서 제목·서명자·진행 상태만 두고, [서명하기] 를 누르면 **이메일을 입력** → 서명자 명단과 맞으면
  그 사람 이메일로 링크를 보낸다(본인 확인은 지금처럼 이메일 인증번호).

## 5. 변경 범위
| 영역 | 내용 |
|---|---|
| DB | `signature_requests.slot`, `party` · `signed_snapshot_hash` · 요청 묶음의 `signing_order` (운영 마이그레이션, 멱등) |
| 편집기 | 서명란 블록(TipTap 노드) — 편집·읽기 두 모드 |
| 서버 | 서명 요청 시 칸 짝짓기 · 우리 측 서명 라우트 · 순서 발송 · 서명본 조립 · 채팅 카드 이메일 확인 |
| PDF | 서명본 렌더 + 서명 증명서 장 |
| 템플릿 | `—` 칸 → 서명란 |

- **Fable 게이트 대상**(R=1): 법적 증빙 · 공개 서명 라우트 변경 · 운영 스키마.
- 옛 문서(Document 모델)의 «이름 입력» 서명 방식은 이번 범위 밖 — 따로 정리한다.
