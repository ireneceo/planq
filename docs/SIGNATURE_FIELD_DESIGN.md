# 서명란 · 서명본 · 우리 측 서명 (2026-09-22 구현)

> Irene: *"문서에 서명이 어떻게 나오는지 알 수 없어서 서명란을 입력하게 된다고 했는데"* → *"고쳐줘."*

## 0. 고치기 전 상태 (조사 결과)
- 서명은 `signature_requests.signature_image_b64` 에 **따로 저장만** 됐다. 문서 본문·공유 링크·PDF 어디에도 안 나왔다.
- 서명자는 문서 아래 별도 칸에 그렸다 — **자기 서명이 어디에 들어가는지 몰랐다.**
- 템플릿(견적·NDA·계약·제안)의 «서명/날인» 칸은 항상 `—` (장식).
- 우리(보내는 쪽) 서명 단계가 없었다. 완료 문구는 «양측 서명» 을 말했다.
- 채팅 카드에 **첫 서명자의 토큰 URL**이 실려 있었다 — 방에 있는 누구나 그 사람 대신 서명 화면에 들어갈 수 있었다.

## 1. 서명란 블록 — 문서 안의 «여기» (구현)
TipTap atom 노드 `signatureField`. 저장 형태는 `<div data-signature-field data-slot data-party data-label>`.

| 속성 | 뜻 |
|---|---|
| `slot` | 칸 번호 1·2… (같은 번호가 둘이면 앞엣것만 쓴다) |
| `party` | `us`(보내는 쪽) / `them`(받는 쪽) |
| `label` | 이름표. 없으면 «보내는 쪽»/«받는 쪽» (갑·을 아님 — Irene 결정) |

- **읽는 공식은 `dev-frontend/src/utils/signatureFields.ts` 한 곳**(편집기의 «다음 칸 번호» + 요청 창의 «칸 배정»이 같이 쓴다).
- 편집기 툴바 버튼: `components/Docs/EditorSignatureButton.tsx` (`data-testid="editor-insert-signature"`).
- 정화기(`utils/sanitizeHtml.ts`)와 변환기(`utils/postContentHtml.ts`)가 이 태그·속성을 살린다 — 지워지면 서명란이 통째로 사라진다.
- 템플릿 4종(견적·NDA·용역계약·SOW)의 `—` 서명 칸을 서명란으로 바꿨다 — 제안서·청구서·회의록에는 원래 서명 칸이 없어 대상이 아니다(`scripts/seed-document-templates.js`). 이미 만든 문서는 그대로.

## 2. 서명본 = 고정본 + 서명 (구현)
**조립은 `dev-backend/services/signedDocument.js` 한 곳이다.** 화면·공유 링크·PDF 가 각자 끼우면 세 곳이 갈라진다.

- `loadSignedView(entity_type, entity_id)` — 취소 제외, 칸 순 정렬, **가장 먼저 만든 요청의 동결분**을 고정본으로.
- `injectSignatures(html, reqs, labels)` — 자리에 서명(이미지·이름·일시·«전자서명 확인됨»)을 끼운다.
  칸에 못 붙은 서명(옛 요청·칸보다 서명자가 많음)은 문서 끝 `.pq-sig-zone` 으로 — **조용히 사라지지 않게.**
- `certificateHtml()` — 문서 제목·지문(SHA-256)·서명자별 이름·이메일·구분·본인확인 시각·서명 시각·IP.
- 결과에 `data-slot`·`data-party` 를 **싣는다** — 서명 화면이 «내 칸» 을 이걸로 찾아 강조한다.

| 보는 곳 | 어떻게 |
|---|---|
| 앱 안 문서 | `GET /api/posts/:id/signed-html` → `PostsPage` 가 본문 자리에 그린다 |
| 공유 링크 | `GET /api/posts/public/:token` 응답의 `signed_html` |
| 서명 화면 | `GET /api/sign/:token` 응답의 `entity.signed_html` (+ 내 칸 강조) |
| PDF | `postPdfHtml(post, author, business, { requests, labels, cert })` |

★ **증명서 장(`cert`)은 멤버 PDF 에만.** 이메일·IP 가 실리므로 링크 소지자 누구나 여는 공개 PDF·공개 페이지에는 넣지 않는다.

## 3. 우리 측 서명 — 로그인이 본인 확인 (구현)
`POST /api/signatures/:id/sign-internal` (`routes/signature_internal.js`).

- 받는 쪽과 다른 것은 **본인 확인 방법 하나**다: 이메일 인증번호 대신 **로그인**.
  나머지(동의 기록·시각·IP·UA·고정본 대조·감사 로그·알림·거래 단계 진행)는 **같은 것**을 남긴다 —
  증거 수준이 갈리면 우리 서명이 계약에서 약한 고리가 된다.
- 서명할 수 있는 사람: `signer_user_id`(요청 창에서 고른 멤버). 없으면 요청자.
- **보내는 쪽에는 메일이 나가지 않는다** → 요청 생성 시 status 는 `sent` 가 아니라 `pending`.
- 화면: 진행 표의 [서명하기] → `components/Docs/InternalSignModal.tsx`.
  그리기 칸은 공개 서명 페이지와 **같은 컴포넌트**(`components/Common/SignaturePad.tsx`).
- **순서는 강제하지 않는다**(Irene: "서명 순서는 알아서 하는 거지"). 모든 칸이 차면 완료.

## 4. 채팅 카드 — 링크를 방에 올리지 않는다 (구현)
- 카드 meta 에서 `sign_url` 을 뺐다. 옛 카드에 남아 있어도 **화면이 쓰지 않는다**(안 쓰면 노출이 멈춘다).
- [서명하기] → 본인 이메일 입력 → `POST /api/sign/request-link` 가 **그 주소로** 링크를 보낸다.
- **열거 방지**: 명단에 없어도 같은 응답(`{sent:true}`). 다르게 답하면 이 문이 «이 사람이 서명자인가» 조회 창구가 된다.
- rate-limit 10분 5회(entity+IP). 만료·취소된 요청에는 보내지 않는다(음성 대조군으로 확인).

## 5. DB (운영 적용 전)
`dev-backend/scripts/migrate-signature-slot.js` (멱등) — `slot INT NULL` · `party ENUM('us','them') DEFAULT 'them'` · `signer_user_id INT NULL`.
- 기본값 `them` 이라 **기존 행·기존 코드와 같다.** 옛 요청은 `slot NULL` → 문서 끝 서명 영역으로 그려진다.
- **코드 배포 전에** 실행한다(컬럼이 없으면 500).

## 7-b. 검증 2차 — 바이트·술어·카드 (2026-09-22, Irene "일일이 검증해놔")

**PDF 를 실제로 뽑아 `pdftotext` 로 읽었다** (HTML 에 있다 ≠ PDF 에 찍힌다):

| | 멤버 PDF | 공개 링크 PDF |
|---|---|---|
| 쪽수 | 2쪽 (본문 + 증명서) | 1쪽 |
| 서명 이미지 | 2개 임베드 | 2개 임베드 |
| «전자서명 확인됨» | ✅ | ✅ |
| 증명서(지문·이메일·IP) | ✅ `8b80df16…` · `Test User` · `127.0.0.1` | **없음** ✅ |
| 이메일·IP 문자열 수 | — | **0** ✅ |

**채팅 카드 — 방에 토큰이 실리지 않는다** (실제 카드 메시지를 만들어 meta 를 읽었다):
`note, title, signers, card_type, entity_id, entity_type` — `sign_url` 없음 · 64자리 토큰 문자열 없음 ·
`signers` 에 **보내는 쪽(우리)은 빠져 있다**(메일 링크가 없는 쪽이라 명단에 세우면 거짓이다).
프론트에서 `sign_url` 을 읽는 곳은 멤버 진행 표의 [URL 복사] 하나뿐이다(의도).

**★ 이 과정에서 실제 결함 1건을 찾아 고쳤다 — 고객은 서명본을 못 보고 있었다.**
`/signed-html` 을 `assertMember` 로 막았는데 **본문(`GET /api/posts/:id`)은 고객(Client)에게도 열린다.**
그래서 고객이 자기 계약서를 앱에서 열면 **본문은 보이는데 서명 칸만 «서명 전»** 으로 남았다 —
사용자에게는 "서명했는데 안 들어갔다" 로 읽힌다. 판정을 `canReadPost()` **한 함수**로 합쳤다
(memory `feedback_predicate_must_match_both_sides`).

| 역할 | 본문 | 서명본 | |
|---|---|---|---|
| owner(멤버) | 200 | 200 | ✅ |
| **고객(Client, 자기 프로젝트 문서)** | 200 | **403 → 200** | ✅ 고침 |
| 비소속자(대조군) | 403 | 403 | ✅ |

양성 대조군으로 증명: 옛 판정(`assertMember`)으로 되돌리니 고객 서명본이 **다시 403**, 고친 판정에서 200.

**템플릿** — `seed-document-templates.js` 실행 후 DB 실측: 견적 2칸 · NDA 2칸 · 용역계약 2칸 · SOW 2칸.
청구서·회의록·제안서는 원래 서명 칸이 없어 대상이 아니다(0칸이 정상).

## 7-d. 전체 여정 카나리 — `--suite signflow` (11검사, 2026-09-22)

조각별 검사(`signature`)와 **다른 축**이다 — 끝까지 걸어야 «중간에 막히는» 것이 드러난다.

★ **인증번호는 메일로만 간다** — 픽스처가 해시를 심어 코드를 아는 상태로 만든다(검증 라우트·화면은 그대로 탄다).
  심지 않으면 이 구간이 통째로 미측정이 된다.

### 이 라운드에서 하니스가 세 번 거짓말했다 (다음 카나리도 같은 함정)
1. **`input.value = ''` 로 지우면 React 상태는 그대로** — 다음 입력이 먹지 않아
   «인증해도 서명 칸이 안 열린다» 는 거짓 실패가 났다. 서버로 직접 쳐 보니 400/200/signed 정상이었다.
   → 사람처럼 **Backspace** 로 지운다.
2. **진행 표는 `<tr>` 이 아니라 styled div** — 태그로 찾으면 늘 0건이라 «메뉴가 없다» 가 거짓으로 통과/실패한다.
   → 확정 손잡이 `sign-row[data-party]` · `sign-row-actions` 를 달았다(§17).
3. **서명을 마친 행에는 어느 쪽이든 메뉴가 없다** — 서명 뒤에 재면 «없다» 가 당연해져 아무것도 증명 못 한다.
   → 그 검사는 **서명 전에** 잰다.

### 유저 입장에서 발견해 고친 것
- **공개 화면의 시각이 `ko-KR` 로 못 박혀 있었다** — 영어 화면에 «Signed at 2026. 9. 22. 오후 6:21» 처럼
  글자는 영어인데 시각만 한국어로 섞였다. 공개 서명 완료·공개 문서·요청 창 3곳을 화면 언어에 맞췄다
  (`utils/dateFormat.publicLocale/formatPublicDateTime` · 멤버 화면은 `useTimeFormat`).

### ★ 여기서 실제 결함 1건 — **거절이 «서명 전» 과 구별되지 않았다**
고객이 거절해도 문서·공유 링크·PDF 에는 **아직 안 한 것과 똑같이** 보였다.
보내는 사람은 그 PDF 를 그대로 남에게 보낸다 — «기다리는 중» 과 «거부당했다» 는 계약에서 완전히 다른 사실이다.
→ `fieldHtml` 에 거절 상태를 넣었다(빨간 «서명 거절» + 이름·시각). **사유는 서명본에 싣지 않는다** —
  그 HTML 은 공개 링크로도 나간다. 사유는 멤버 진행 표에만 남긴다(요청한 사람은 이유를 알아야 한다).
- 실측: 거절 전 빈칸 2·거절표시 0 → 거절 후 빈칸 1·거절표시 1 · 공개 링크에도 표시 · 사유 노출 0.
- 회귀: 여정 카나리 ⑫ (거절 칸 800×103 그려짐 · 사유 서명본 없음 / 진행 표 있음).
