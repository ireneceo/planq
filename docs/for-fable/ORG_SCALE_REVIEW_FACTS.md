## Fable 에게 묻는 것
1. 10~20명(그리고 30~50명) 조직이 **처음 3개월 안에 «부족하다/불편하다» 고 느낄 것**은 무엇인가 — 기능 공백과 구조 공백을 갈라서.

## 3. 역할·권한
- 역할 4개: owner · admin · member · client(+ platform_admin). 중간관리자(부서장·PM) 역할 없음 — 프로젝트 PM 은 프로젝트 안에서만.
- 메뉴 권한: **사람 × 메뉴 11개 × none/read/write 를 한 명씩** 설정(`business_member_permissions`). 역할 묶음·부서 일괄·템플릿 없음(grep 0). 20명 × 11칸 = 220칸 수동.
- 10-07 감사 #12·#13·#14(CONFIRMED, 수정 여부 이 묶음에서 미확인): admin 이 화면·서버에서 다르게 정의 · 메뉴 «숨김» 이 사이드바에 반영 안 됨. 10-16 «메뉴 편집»(개인 숨김)은 권한 아님.
- 감사 로그 화면: **플랫폼 관리자 전용**(`routes/admin.js:880 /audit-logs`). 워크스페이스 owner 가 «누가 무엇을 바꿨나» 를 볼 화면 없음(기록은 AuditLog 에 남는다).
- SSO(구글 워크스페이스·MS SAML)·SCIM 자동 프로비저닝 없음(grep 0). 로그인 = 이메일/비밀번호 · 구글 · 애플 개인 로그인.
