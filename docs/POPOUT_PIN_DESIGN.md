# 팝아웃 "항상 위" 설계

**확정: 2026-08-20 (Fable 설계 게이트)** · 관련 운영 신고 #26 · #43 · #258 · #280 · #286

---

## 0. 이 문서의 옛 사양은 **기각됐다**

옛 주 사양이었던 **"팝아웃에서 핀을 누르면 메인 탭이 대신 고정창을 연다"(릴레이)** 는
실클릭 재현으로 반증됐다. 근거:

- 팝아웃에서 실제 클릭 → 방송 → 메인 탭 `requestWindow()` = `NotAllowedError: Document PiP requires user activation`
- HTML 스펙상 user activation 은 **같은 최상위 브라우징 컨텍스트**의 same-origin 프레임에만 전파된다.
  opener 를 건너 다른 최상위 창으로는 전파되지 않는다. 스펙과 실측이 같은 방향이다.
- 한때 "전파된다" 는 측정이 있었으나 자동화 도구(CDP `userGesture`)가 메인 창에도 가짜 조작을
  심은 오염이었다. **측정 도구가 조작을 심을 수 있다는 것을 잊지 말 것.**

이 문단을 지우지 말 것. 지우면 반증된 구조가 다시 구현된다.

## 1. 물리 (실측 · 2026-08-19~20, xvfb + puppeteer 실클릭)

| # | 사실 |
|---|---|
| 1 | 팝아웃 창이 **자기 클릭으로** `documentPictureInPicture.requestWindow()` 호출 → **성공** |
| 2 | 그 뒤 **팝아웃 창을 닫으면 고정창도 함께 소멸** (browser targets 에서 사라짐) |
| 3 | 팝아웃의 사용자 조작은 메인 탭으로 **전이되지 않는다** |

**귀결: "팝아웃 창 안에서 핀 1클릭" 은 웹에서 어떤 변형으로도 불가능하다.**
- 릴레이 → 3번으로 막힘
- 팝아웃 소유 → 2번 때문에 팝아웃 창이 계속 살아 있어야 하고, 그게 #258 의 "창 하나 더" 다
  (홀더 축소·최소화는 웹 API 로 불가 — 그게 옛 구조였고 바로 그 신고의 원인이었다)

## 2. 확정 사양 — **여는 클릭이 곧 "항상 위"**

핀이라는 **행위를 없앤다.** 도크에서 도구를 여는 그 클릭이 고정이다.

데스크탑 · Document PiP 지원 브라우저에서 도크의 도구 행을 클릭하면:

| 상태 | 동작 |
|---|---|
| 고정 자리가 비어 있음 | **그 도구를 바로 고정창(PiP)으로 연다.** 클릭 1회, 창 1개 |
| 이미 **다른** 도구가 고정 중 | **일반 창으로 연다. 기존 고정창은 절대 자동으로 닫지 않는다** |
| 이미 **같은** 도구가 고정 중 | 그 창을 앞으로만 가져온다(`pinOwner.focus`). 창 수 불변 |
| 미지원 브라우저 · 모바일 | 기존 폴백 그대로 (일반 창 / in-app) |

- **핀 아이콘은 어디에도 없다.** 도크 행 옆 핀 버튼, 일반 팝아웃 헤더의 핀 모두 삭제.
  남는 핀 계열 UI 는 **고정창 안 헤더의 해제 버튼 하나**뿐 — #258 의 요구 그대로.
- **자동 축출 폐지.** "다른 창 열면 기존 팝아웃 닫히잖아"(Irene) 를 만들지 않는다.
- 일반 창으로 열려 있던 도구를 항상 위로 올리려면: 고정 자리를 비운 뒤 도크에서 그 도구를 다시
  클릭한다 → 고정창으로 열리고 기존 `pin-engaged` 방송이 옛 일반 창을 자기닫기시킨다
  (도구당 창 1개 불변식 유지).

### 브라우저 한계는 숨기지 않는다

고정 자리가 차 있을 때 도크 하단에 **한 줄**로만 말한다 (문단 금지):

- ko `항상 위 창은 브라우저에서 1개만 열 수 있어요 — 다음 도구는 일반 창으로 열려요`
- en `The browser allows only one always-on-top window — other tools open as regular windows`

**"여러 개를 동시에 항상 위" 는 웹(PWA 포함)에서 불가능하다.** Chrome 의 하드 리밋이고,
일반 창에는 항상-위 API 자체가 없다. 필요해지면 **Electron 데스크탑 앱**이 유일한 경로다
(프론트 재사용 ~95% — standalone 팝아웃 라우트를 도구별 `BrowserWindow({alwaysOnTop:true})` 에
그대로 싣는다 / 백엔드 무변경 / 신규는 셸·세션·알림·자동업데이트·패키징 + 코드서명 비용).
**지금 착수하지 않는다** — 이 사양을 먼저 쓰고, 그래도 2개 이상 동시 고정이 매일 필요하면
그때 별도 안건으로 올린다.

## 4. 건드리면 회귀하는 것

- `utils/pinOwner.ts` 모듈 싱글턴 구조(도크는 공개 표면·`/memo` 에서 언마운트된다 — 상태를 거기 두면 고정창이 고아가 된다)
- `pinOwner` 에 `resizeTo` / 자기 창 `close` 부작용을 **넣지 말 것** (홀더 시대의 잔재. 지금 소유자는 사용자의 메인 탭이다)
- `body.dataset.pipActive` reload 가드 (빠지면 배포마다 고정이 죽는다)
- 복원 칩 · `pin-intent`/`pin-ack` 크로스탭 프로토콜 · 고정창 폴링 감지
- `pin-engaged` 일반 창 자기닫기 (일반 창 → 고정 승격 경로의 몸통)
- 고정창 헤더 해제 버튼 + 녹음 중 확인 다이얼로그
- 모바일 in-app 폴백 · `supportsPin()` 입력방식 판정(뷰포트 폭으로 바꾸지 말 것 — 팝아웃 창이 520px 이라 항상 참이 된다)
