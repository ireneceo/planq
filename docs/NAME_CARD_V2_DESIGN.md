> Irene 원문(10-19): *"명함에서 회사·브랜드는 달라야 해. 회사는 하나지만 브랜드는 여러개일 수 있잖아. 그리고 워크스페이스마다 다른 명함 나와?
> 아니면 동기화돼? 명함등록하고 이 워크스페이스의 기본명함, 이렇게 설정되게 할까? 그럼 어디 보여줄때 이 워크스페이스를 통하면 그게 보이게.
> 지금은 보는 곳 없지? 그리고 브랜드 여러개 여러 사이트일 수 있고 브랜드 이름/간략설명/사이트나 sns여러개. 있을 수 있어. 이 워크스페이스에서는
> 기본 브랜드가 있을 수 있지만 회사랑 같이 표시를 알아서 하면 될 일인 것 같아. 개인 것도 있을 수 있고. 정리 좀 더 잘해줄 수 있어?

> 영어는 추가로 검색해서 넣을 수 있게 해줘. 이건 조직에 멤버추가하면서 직무/역할 선택하는 거에서 연결할 수 있어? 이거 제대로 검토해야 하면 fable 기다려."*

## 0. 지금 있는 것(사실)
| 무엇 | 어디 | 모양 |
|---|---|---|
| 워크스페이스 회사 정보 | `businesses` | `legal_name(_en)`(법인명) · `name` · `brand_name(_en)` · `brand_tagline(_en)` · `brand_logo_url` · `brand_color` · `address` · `phone` · `email` · `website` — **브랜드 1개 고정** |
| 멤버 직책 | `business_members.job_title` | 자유 글자 100자(대표·팀장…) — 설정 > 멤버·조직도·내 프로필에서 고침 |
| 멤버 역할 | `member_roles` 사전 + `business_members.default_role`·`project_members.role` 글자 | 워크스페이스 사전(기획·디자인·제작·영업·마케팅·운영·고객지원 + 커스텀) — **«프로젝트에서 맡은 일»**(docs/MEMBER_ROLES_DESIGN.md) |
| 부서·팀 | `departments`·`teams` | 조직도 |
| 직무(무슨 일을 하는 사람인가) | **없음** | — |
| 명함을 보는 곳 | 공개 `/c/:token` 하나 | 워크스페이스 안에서 명함을 보여 주는 화면은 **없다**(Irene 지적 맞음) |

**세 축을 섞지 않는다** — 직책(위계: 대표·팀장) / 역할(이 워크스페이스·프로젝트에서 맡은 몫: 기획·디자인) / **직무(직업 자체: UX 디자이너·세무사·백엔드 개발자)**.
명함에 찍히는 것은 보통 «직책 + 직무(또는 부서)» 다.

## 1. 회사 ↔ 브랜드
### 안 A (권고 초안) — 워크스페이스 브랜드 목록 + 개인 브랜드
- 새 표 `brands`: `id · owner_kind ENUM('business','user') · business_id NULL · user_id NULL · name · name_en · tagline(간략 설명) · tagline_en · logo(파일) · links JSON [{kind:'website'|'instagram'|…, url}] 최대 8 · sort_order · is_default(워크스페이스 기본 브랜드)`.
  - 워크스페이스 브랜드: owner/admin 이 설정 > 회사 정보(또는 «브랜드» 칸)에서 관리 · 멤버 이상이 명함에 고를 수 있음.
  - 개인 브랜드: 내 명함 화면에서 내가 만들고 나만 씀(개인 사업·작가명 등).
  - 옛 `businesses.brand_*` 1개 → 그 워크스페이스의 첫 브랜드로 옮기고(is_default) 옛 칸은 남겨 둔다(읽는 곳이 많다 — 영수증·공개 페이지 등. 별 일로 정리).
- 회사(법인)는 **워크스페이스 하나 = 회사 하나**로 본다(`legal_name`). 개인 명함은 회사 칸을 직접 쓴다(자유 글자).
- 명함 칸: `company`(회사명 글자 — 출처 워크스페이스면 법인명/워크스페이스 이름으로 채움) + **`brand_ids` 여러 개**(고른 브랜드 — 표시 순서). 명함에 회사와 브랜드를 «알아서» 같이 표시: 회사 == 브랜드 이름이면 한 줄, 다르면 «브랜드 · 회사» 두 층 · 브랜드마다 간략 설명·링크 묶음.
- 명함에 브랜드를 «연결»(라이브)할지 «복사»(스냅샷)할지 → **연결 권고**(브랜드 사이트를 바꾸면 모든 명함이 따라간다 — 브랜드는 회사 자산이다. 명함 자신의 칸(이름·직책·연락처)은 v1 처럼 명함 값). 공개 응답은 브랜드를 펼쳐 실어 준다(화이트리스트). 워크스페이스에서 브랜드를 지우거나 멤버가 나가면 그 명함에서 브랜드가 빠진다(공개 페이지에서 사라짐).
### 안 B — 브랜드도 명함 칸(복사)
- 명함마다 브랜드 블록을 직접 입력. 단순하지만 같은 브랜드를 명함마다 고쳐야 하고 워크스페이스 기본 브랜드 개념이 없다.

## 2. 워크스페이스마다 다른 명함? — «워크스페이스 기본 명함»
- 명함은 계정 것(v1 그대로) — 동기화가 아니라 **선택**이다: `business_members.default_card_id`(사람 × 워크스페이스, 내 명함 중 하나 · NULL 가능).
- 내 명함 화면에서 «이 워크스페이스 기본 명함으로» · 명함 카드에 «○○ 워크스페이스 기본» 칩.
- **보이는 곳(새로)** — 같은 워크스페이스 사람이 그 사람을 볼 때:
  ① 사람 아이콘 팝오버(`UserInfoPopover` — 채팅·업무 등 이름 누르면 뜨는 것)에 [명함 보기] → 그 워크스페이스 기본 명함(공개 꺼져 있어도 워크스페이스 안에서는 보임?)
  ② 설정 > 멤버 상세 · 조직도 사람 카드에 같은 [명함 보기].
  ③ (선택) 고객이 보는 곳 — 고객 포털·게스트 링크의 담당자 표시에 담당 멤버의 기본 명함 링크. **고객에게 보이는 것은 공개 링크가 켜진 명함만**.
  - 판정 질문: 워크스페이스 안에서 «공개 꺼진» 기본 명함을 동료에게 보여 줄 것인가(안: 보여 준다 — 같은 워크스페이스 멤버 범위, 프로필 사진과 같은 축) vs 공개 켜진 것만.
- 기본 명함이 없으면 [명함 보기] 를 그리지 않는다.

## 3. 직무 체계 — «온세상 모든 직무»
### 데이터 출처(조사 사실)
| 출처 | 규모·언어 | 이용 조건 | 판단 |
|---|---|---|---|
| **ESCO v1.2.x**(EU 집행위) | 직업 약 3,000(+대체 이름 다수) · ISCO-08 4단계에 연결 · 28개 언어(영어 포함, **한국어 없음**) · CSV | EU 공개자료 재사용(출처 표시) — **상업 이용 가능으로 알려짐(확인 필요)** | 영어 원본·구조로 적합 |
| **ISCO-08**(ILO) | 4단계 436 단위군 | 국제 표준(공개) | 상위 분류(대·중·소) |
| 한국표준직업분류(KSCO 7차, 통계청) | 세세분류 약 1,200 · 한국어 | 공공데이터포털 파일은 **공공누리 4유형(상업 이용 금지·변경 금지)** | **그대로 쓰면 안 된다** |
- 그래서 한국어는 **ESCO 영어 직업명을 우리가 번역**(LLM 일괄 번역 + 사람 검수 표본)해 우리 자산으로 둔다 — 원문 영어는 ESCO 그대로(출처 표시).
### 모델
- 플랫폼 공통 사전 `occupations`(business_id 없음, Q위키처럼 플랫폼 콘텐츠): `id · esco_uri · isco_code(4) · name_en · name_ko · alt_en JSON · alt_ko JSON · description_en(짧게) · …` + ISCO 상위 그룹 표 `occupation_groups`(1~4단계, ko/en).
- 검색 `GET /api/occupations?q=`(인증, 계정 언어 우선 + 영어 동시 검색, 대체 이름 포함, FULLTEXT ngram) — 계정 언어 = `users.language`(지금 ko). 영어는 «영어로도 찾기» 가 아니라 **한 검색창에서 둘 다** 맞춘다.
- 사전에 없으면 «직접 입력»(자유 글자) 허용 — 명함·멤버에 `occupation_id` 또는 `occupation_custom`.
### 어디에 연결
- 명함: 새 칸 «직무»(`occupation_id`/`occupation_custom`, 표시 = 계정 언어 이름 · 영문 명함 표시는 name_en).
- 멤버: `business_members.occupation_id`/`occupation_custom` — **설정 > 멤버(상세)·초대(여러 명 초대 포함, ORG_STAGE0 설계와 같은 폼)·조직도**에서 고른다. 명함을 그 워크스페이스로 채울 때 멤버의 직무가 들어온다.
- 역할(member_roles)과는 **다른 칸**으로 둔다 — 역할 = 이 워크스페이스·프로젝트의 몫(짧은 사전, 업무 자동 배정·AI 가 글자로 읽는다), 직무 = 사람의 직업(긴 표준 사전). 합치면 역할 사전이 3,000개가 되고 업무 추출 매칭이 깨진다.
- (선택) 직무 → 역할 제안: 직무의 ISCO 대분류로 역할 사전 후보를 미리 고른다 — 이번엔 안 함(제안만 후속).

## 4. 범위·순서(제안)
1단계 — 브랜드 표·워크스페이스 브랜드 관리·명함 회사/브랜드 분리·공개 페이지 표시 · 워크스페이스 기본 명함 + 팝오버/멤버 상세 [명함 보기].
2단계 — 직무 사전 데이터 구축(ESCO 가져오기·한국어 번역·검수) + 검색 API + 명함·멤버·초대 연결.
(운영: 표 3~4개 마이그레이션 · ESCO 데이터 적재 스크립트 · v1 은 아직 운영 미배포라 v1+v2 를 한 번에 배포 가능)

## 5. Fable 에 묻는 것
1. 브랜드: 안 A(표 + 연결) / 안 B(명함 칸 복사) — 연결이면 브랜드 삭제·멤버 이탈 때 명함·공개 페이지 처리.
2. 옛 `businesses.brand_*` 이관 방식(남겨 둘지·읽는 곳 전환 범위).
3. 워크스페이스 기본 명함: 표시 범위(동료에게 공개 꺼진 명함도 보이나) · 보여 주는 곳 우선순위 · 고객에게 보여 줄지.
4. 직무: 출처(ESCO+자체 번역)·라이선스 판단 · 플랫폼 사전 모델 · 역할과 분리 · 멤버/초대 연결 범위 · 1·2단계 나눔.
5. 빠진 위험(개인정보·공개 표면 확장·검색 성능·번역 품질 검증 방법).
