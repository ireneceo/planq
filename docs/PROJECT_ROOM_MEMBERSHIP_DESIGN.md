# 프로젝트 대화방 — 방마다 «프로젝트 멤버 자동 참여» (2026-11-24 · 초안 [Opus] → Fable 설계 판정)

> Irene: *"같은 프로젝트여도 채팅방에 막 다 들어가면 안돼. 내부는 모두 들어가더라도 고객이나 다른 채팅방 만들면 그건 각각 필요해서 만드는 거란 말이야. 유연하게 설정되게 해주고 갑자기 다른 사람이 들어와서 깜짝놀랄 일 없게 검토 해"*

## 지금 (36826943 · cb9f1b03 · 11-16)
사람이 프로젝트 방에 **본인 선택 없이** 들어가는 문:

| # | 문 | 지금 들어가는 방 |
|---|---|---|
| A | `PUT /api/projects/:id/members` 든 멤버 (`syncProjectMemberChannels` → `joinProjectMemberToChannels`) | 그 프로젝트 **모든** 방(내부·고객·따로 만든 방·보관 포함) |
| B | 대표·관리자가 프로젝트 방 하나에 멤버 추가 (`POST /conversations/:biz/:id/participants` → `syncProjectMember`) | 그 방 + 프로젝트 멤버가 되며 **다른 모든 방** |
| C | 대표·관리자가 프로젝트 방을 만들며 사람을 넣음 (`POST /conversations/:biz` → `syncProjectMember`) | 그 방 + **다른 모든 방** |
| D | 고객 채널 새로 생김 (`ensureClientChannel` · `ensureProjectCustomerChannel` — 고객 추가·초대 수락·고객 링크) | 새 고객방에 **프로젝트 멤버 전원** |
| E | 프로젝트 만들 때 채널(`project_actions` channels) | 넘긴 참여자, 없으면 프로젝트 멤버 전원 (만드는 사람이 화면에서 보고 고름 — 놀람 아님) |
| F | 고객 초대 수락 → 자기 고객방 (`clientOnboarding`) | 자기 회사 방만 (문제 없음) |

고객방에 내부 사람이 갑자기 늘면 **고객이 참여자 목록에서 본다** — Irene 가 말한 «깜짝» 의 주된 모양.

## 제안
1. **칸** `conversations.project_auto_join TINYINT(1) NOT NULL DEFAULT 0` — 프로젝트 방(project_id 있음)에서만 뜻이 있다.
   켜짐 = «이 프로젝트 멤버는 모두 이 방에 들어온다». 꺼짐 = 방에 직접 초대한 사람만.
2. **기본값**
   - 프로젝트 만들 때 생기는 **내부** 방 → 켬 (E).
   - **고객 채널**(어느 문이든) → 끔. 바꿀 수는 있다(켜면 고객이 보는 방에 내부 전원이 들어간다는 확인).
   - Q talk 에서 프로젝트에 붙여 새로 만든 방 → 끔(새 방 창에서 «프로젝트 멤버 모두 자동 참여» 체크로 켤 수 있음, 내부 방만 보임).
3. **A·B·C 의 «다른 방» = 켜진 방만** (`joinProjectMemberToChannels` 가 `project_auto_join=1` 만 고른다).
   B·C 의 «프로젝트 멤버로도» 는 그대로(작업대 not_project_member 막힘 #473 을 다시 만들지 않는다).
4. **D 새 고객방 처음 참여자** = 만든 사람 + 프로젝트 PM(is_pm, owner 포함) + Cue. 전원 아님.
5. **빼기(프로젝트에서 빠짐)는 그대로 모든 프로젝트 방에서 뺀다** — 넣기만 좁히고 빼기는 넓게(숨은 프로젝트 대화를 계속 읽는 구멍 = 11-16 Fable FAIL 1).
6. **켜고 끄기** `PUT /api/conversations/:biz/:id/auto-join {on}` (또는 기존 설정 PUT 에 칸 추가) — 권한 = 프로젝트 멤버 관리와 같은 술어(`canManageProjectMembers`: 대표·관리자·플랫폼 관리자).
   켜면 지금 프로젝트 멤버 중 빠진 사람이 **그 자리에서 들어간다** — 화면이 확인창에 «N명이 들어갑니다(이름)» 를 먼저 보여 준다(고객방이면 «고객이 보는 방» 경고 한 줄 더).
   끄면 아무도 나가지 않는다(나가게 하려면 참여자에서 직접 내보낸다).
   전체(team)·PlanQ 안내방·프로젝트 없는 방은 409.
7. **화면 문구** — 프로젝트 멤버 추가 안내 «추가한 멤버는 이 프로젝트의 채팅에도…» → «‘자동 참여’ 가 켜진 채팅에만 들어갑니다(고객방·따로 만든 방은 직접 초대)». 채팅 설정 결과 문구 projectAdded 도 같은 뜻으로.
   채팅 설정에 스위치 한 줄(프로젝트 방일 때만, 권한 없으면 읽기 전용 표시).
8. **옛 데이터 (마이그레이션, 멱등, 아무도 빼지 않음)** — 칸 추가 후: 프로젝트 방 중 `channel_type='internal'` 이고 지금 참여자가 그 프로젝트 사람 멤버 전원을 덮는 방 → 1. 나머지 0.
   이미 들어가 있는 사람은 그대로 둔다(빼면 반대로 «갑자기 사라짐»).

## Fable 설계 판정 (2026-11-24 · NEEDS-CHANGE → 아래대로 구현 · [Opus])
dev 실측: 프로젝트 방 114개 중 고객방 대부분이 이미 멤버 전원 참여(11-16 연동 결과) — «전원을 덮는다» 는 오염된 신호라 초안 8번 백필을 좁혔다.

1. 칸 `conversations.project_auto_join` — 프로젝트 없는 방은 늘 0(연결 끊기도 0으로). **고객 응답에는 싣지 않는다.**
2. 자동 참여는 **사건**이다 — 들어가는 순간은 ①프로젝트 멤버가 되는 관리 문(PUT members·방 초대·방 만들며 넣기·인수인계) ②스위치를 켜는 순간뿐. 주기 보정·조회 때 채우기 없음(스스로 나간 사람이 되끌려오지 않게).
3. 위 문들은 `project_auto_join=1` 방만(보관 포함). 방 초대·만들기의 «프로젝트 멤버로도» 는 유지(#473). 응답 `joined_rooms`.
4. 새 고객방(두 생성 함수 → `initialCustomerRoomStaff` 한 함수) = 만든 사람(없으면 그 고객을 붙인 `project_clients.invited_by`, 지금도 프로젝트 멤버·활성 직원일 때) + PM + Cue, 사람 0명이면 대표. 다른 고객방 참여자 따라가기 안 함. 고객방은 어느 문이든 끔.
5. 프로젝트 만들 때 채널: 내부 = 목록 없음/전원이면 켬, 일부면 끔 · 고객 = 끔, 목록 없으면 만든 사람 + Cue.
6. 인수인계(`memberHandover`)도 새로 멤버가 되면 켠 방에.
7. 고객→멤버 전환(`clientToMember`)은 자동 참여 **안 함**(주석으로 박음).
8. 빼기는 그대로 모든 프로젝트 방에서(직접 초대된 방 포함, owner 예외).
9. `PUT /api/conversations/:biz/:id/auto-join {on, expect_user_ids, dry_run}` — 권한 `canManageProjectMembers`(PM 아님) · 켤 때 명단이 다르면 409 `auto_join_changed` + 새 명단 · 끄기는 아무도 안 나감 · 전체·안내·프로젝트 없는 방 409 · 감사 `conversation.auto_join`, 참여 감사 via `auto_join_on`.
10. 화면 — 채팅 설정 스위치(권한 없으면 읽기 전용) · 켤 때 명단 확인창(고객방이면 «고객이 봅니다») · 새 방 창 체크(내부 + 기존 프로젝트 + 권한자만) · 프로젝트 멤버 안내 문구.
11. 마이그레이션 `scripts/migrate-project-auto-join.js` — 칸 + 한 번만 백필(표시 = audit_logs `migration.project_auto_join_backfill`, 칸 존재로 판정 안 함) · 프로젝트마다 보관 안 된 첫 내부 방이 지금 멤버 전원을 덮을 때만 켬 · 아무도 빼지 않음 · «11-16 이후 자동으로 고객방에 들어갔고 말한 적 없는 (방, 사람)» 읽기 전용 목록 출력. 되돌리기 = 칸을 0으로.
