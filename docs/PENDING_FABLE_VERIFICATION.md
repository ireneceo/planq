## A. 소급 검증 — 이미 운영에 나가 있음 (롤백 아님, 사후 확인)

Fable 사용량이 떨어진 뒤 Opus 자체 검증만으로 배포된 4건. **위험도 순.**

### A-1. `c6f276bd` 메일 성능 — 본문 base64 이미지 분리 + 응답 압축  ★최우선
- 본문의 97~100%가 base64 이미지였고 nginx `gzip_types` 주석 처리로 JSON 이 압축조차 안 되고 있었다.
  `services/emailInlineData.js` 신설(내려보낼 때만 `data:` → `cid:planq-embed-N`, **DB 무변형**),
  `GET .../messages/:messageId/embedded/:index` 신설, `compression` 미들웨어 추가.
- **반증 항목**
  1. 실 메일 3건 이상에서 본문 이미지가 **깨지지 않는지**(iframe contentFrame 으로 특정해 측정할 것 —
     첫 프레임을 보면 이미지 없는 스레드도 "정상" 으로 세는 함정이 있다. Opus 가 그 함정에 빠졌다)
  2. 접힌 메시지의 이미지가 **요청되지 않는지** (펼칠 때만 요청)
  3. `embedded/:index` 의 멀티테넌트 — 타 워크스페이스 스레드 404/403
  4. strip/extract 의 **인덱스 규칙 일치** — 4KB 미만·이미지 아닌 data URI 제외 조건이 양쪽 같은지
  5. 압축이 Stripe webhook(raw body 서명검증)에 영향 없는지
  6. 회선 바이트는 `response.buffer()` 가 0 을 돌려준다 — **CDP encodedDataLength** 로 잴 것

### A-2. `c2a47409` 별칭 문구 + 주소별 서명 UI

## B. 배포 대기 — 커밋됨, 운영 미반영

### B-1. 보내는 주소 통합 + 서명 출처 라벨
- `보내는 계정` / `보내는 주소` 두 칸 → **주소 한 칸**(값 `accountId:aliasId`). 개인 메일함 주소가
  목록에 나온다. 라벨은 `표시이름 <주소>`. 서명 출처 `account` 라벨 "개인 서명" → **"기본 서명"**
- **반증**
  1. 주소를 고르면 **계정이 실제로 따라 바뀌는지** — 개인 주소 선택 후 발송 시 그 계정의 SMTP 로
     나가는지(account_id 가 서버에 정확히 전달되는지). 여기가 이 변경의 급소다
  2. 별칭 초기화 effect 를 없앴다 → **다른 계정의 별칭 id 가 남아 `alias_not_owned` 400 이 나지 않는지**
     (계정 A 별칭 → 계정 B 주소 → 다시 A 로 왕복)
  3. 개인 주소로 실제 발송 시 **발신자 이름·서명이 그 계정 것**인지
  4. 답장 화면 주소 목록이 같은 형식이고 기존 자동 선택(받은 주소로 답장) 이 깨지지 않았는지
  5. 서명 배지: 회사 주소 선택 시 "기본 서명 · help@irenewp.com", 전용 서명 있는 주소는
     "이 주소 전용 서명" 으로 바뀌는지 · ko/en 양쪽
  6. 계정이 1개뿐인 워크스페이스에서 주소 칸이 사라지지 않는지(옵션 1개일 때 렌더 조건)
