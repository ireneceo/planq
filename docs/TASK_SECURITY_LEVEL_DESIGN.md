# 업무 공개 범위·보안등급 — 문서·일정과 같은 두 축 (2026-10-12)

> Irene: *"업무에서도 보안이랑 공유범위 있어야 하지 않아?"*
> → 1차(«내부 업무» 한 축)를 보고 받고: *"문서랑 일정처럼 워크스페이스 특정 멤버 나만보기 등 같은 기능 넣어달라고 한거야.
>   그리고 보안등급도 있잖아. 모든 기능들은 추가할 때 기존 기능 그대로 반영해야지 왜 마음대로 바꾸고 그래?"*
> 그래서 **문서(Q docs)·일정의 규칙과 컴포넌트를 그대로** 업무에 붙였다. 1차의 «내부 업무(고객에게 숨김)» 뜻은 버렸다.

## 1. 칸 (tasks)
| 칸 | 값 | 기존 행 |
|---|---|---|
| `vlevel` | L1 나만 보기 · L2 특정 프로젝트(= 이 업무의 프로젝트) 또는 특정 멤버 · L3 워크스페이스 · L4 외부 | L3 (지금 보이는 그대로) |
| `target_member_ids` | L2 «특정 멤버» 대상(이 워크스페이스 멤버만, 고객·AI 불가) | NULL |
| `security_level` | general · internal · confidential — 일반 밖이면 외부 공유(공개 링크·게스트 링크) 차단 | general |

운영 스키마: `dev-backend/scripts/migrate-task-security-level.js`(멱등, 배포 슬롯, 코드보다 먼저).

## 2. 누가 보나 — 판정 한 곳 `middleware/access_scope.canAccessTask` · `taskListWhere`
1. **이름이 박힌 사람**(작성·담당·요청·컨펌자)은 범위와 무관하게 본다 — 일정의 «초대받은 참석자» 와 같은 규칙.
   (업무는 관계자가 여럿이라 문서의 «작성자만» 을 그대로 쓰면 담당자가 자기 일을 못 본다.)
2. 멤버 — L3·L4 전부 · L2 «특정 멤버» 는 지정된 멤버 · L2 «프로젝트» 는 그 프로젝트 멤버 · L1 은 1번만.
   owner/admin 은 L2 전부를 보되 **남의 L1 은 못 본다**(2026-10-09 D2 — 문서·일정·Q info 와 같다). 볼 수 없으면 고치기·지우기도 404.
3. 고객 — 종전 관계(대화 참여·프로젝트 고객)로 닿되 L1·L2 «특정 멤버» 는 안 보인다(문서 `canAccessPost` 의 L1 제외와 같은 선 + «선택한 멤버만» 약속).
4. 보안등급은 읽기 축이 아니다 — 문서와 같다(고객은 기밀 프로젝트 문서도 본다). 외부로 나가는 문만 막는다.

## 3. 바꾸기 — `services/taskVisibility.normalizeVisibilityPatch` 한 곳(생성·수정이 같이 쓴다)
- 바꾸는 사람: 작성자 ∨ owner/admin, 고객 제외(`task_actions.FIELD_RULES`) — 문서 `/visibility`·`/security-level` 과 같은 집합.
- L2 는 대상이 있어야 한다(지정 멤버 또는 업무의 프로젝트) — 없으면 400.
- L4 는 보안등급 일반일 때만(403). 등급을 일반 밖으로 올리면 L4 → L3.
- 좁히면(L1·L2) 또는 등급을 올리면 나가 있던 공유 링크를 끊는다(`share_helper.shareOffPatch`, 시리즈 전파 포함).
- 복사·반복 회차·시리즈 «이후 모두/전체» 는 그대로 승계.

## 4. 바깥으로 나가는 문
- 공유 링크 발급: 업무 보안등급 일반 밖 **또는** 실릴 첨부의 등급(2026-09-27 «첨부에서 파생» 은 OR 로 유지).
- 게스트 프로젝트 링크: 게스트 문서와 같은 선 — 관계 공개 범위(L3·L4·프로젝트 L2) ∧ 일반.
- 실시간: `services/taskRoom.emitTask` 한 문 — L1·L2 는 볼 수 있는 사람의 `user:<id>` 방에만 행, 그 밖의 워크스페이스·프로젝트 방엔 `task:deleted` 신호만.
- 보는 사람을 모르는 저장 보고서(워크스페이스 주간보고·단위 보고서·월간 리포트 PDF)·메일 브리핑: 워크스페이스 공개(L3·L4) 업무만 제목으로 싣는다.
- 보는 사람이 있는 화면(프로젝트 업무·캔버스·보고서·타임라인·히스토리·파일 탭·작업대·통계 업무 탭·고객 타임라인·관련 업무·Cue·AI 초안·일정 조정·템플릿 만들기): `taskListWhere`/`canAccessTask` 를 건다.

## 5. 화면 — 문서와 같은 컴포넌트
업무 상세·업무 추가: `VisibilityChip` → `VisibilityChangeModal`(문서와 같은 라디오) · 보안등급 `PlanQSelect`(일반·내부·기밀, `useSecurityLevelLabel`).
상세의 «외부에 공유 링크로 보내기» 는 기존 공유 창으로. 추가 폼은 외부(L4)를 숨긴다(만들기 전엔 링크가 없다).

## 6. 남은 것(이번 범위 밖)
- 업무 목록 행의 공개 범위 표시(문서 목록의 RowVisChip 같은 것) — 아직 없음.
- 개인 주간 회고·대시보드 «확인 필요»·포커스·근태는 본인 관계 업무만 다뤄 손대지 않았다.
- AI 에이전트(ChatGPT·Claude) 도구는 범위·등급을 바꾸지 못한다(입력 칸 없음) — 읽기는 같은 판정.
