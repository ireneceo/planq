## 0. 지금 (코드 사실)
- 편집기 TipTap v3, 본문 정본 `posts.content_json`. 공동 편집(Yjs) 없음.
- 자동저장 PUT `/api/posts/:id` + 낙관적 잠금(`base_updated_at` ≠ `posts.updated_at` → 409) → 화면은 자동저장을 멈추고 «다른 사람이 수정» 배너. **나중에 저장하는 쪽이 막힌다.**
- 편집 권한 `routes/posts.js canEditPost` — 볼 수 있으면 고칠 수 있다(L1 작성자만 · 고객 불가).
- 변경 기록 `services/postRevisions` — 스냅샷 · 같은 사람 10분 묶음 · 문서당 50 · 되돌리기는 새 행.
- 실시간은 신호만(`post:updated`). 문서 댓글 있음.

## 1. Fable 판정 — B 먼저, A(구글독스식 글자 단위 동시 입력)는 B 를 써 본 뒤 별도 승인

  어긋나면 «서명한 문서와 보이는 문서가 다르다» 같은 되돌리기 어려운 사고. 몇 주 규모.
- B 는 지금 장치(소켓 신호·낙관적 잠금·변경 기록·초안 보존) 위에 얹는 1주 안팎 · 되돌리기 쉬움 · A 로 가는 길을 막지 않음.

## 2. B 범위 (v1)
1. **누가 보고·쓰고 있나** — 문서별 소켓 방 `post:<id>`(서버가 명단 보유), 밴드2 에 아바타 + «○○ 편집 중»(최근 30초 입력).
   보이는 대상 = 그 문서를 편집할 수 있는 사람만(고객에게 멤버 이름 노출 금지). 권한이 줄면 방에서 내보냄(socketRevoke 같은 문).
2. **쓰기 전 경고** — 남이 편집 중이면 한 줄 안내. 잠그지 않는다.
3. **안 치는 동안 남의 저장이 바로 보인다** — `post:updated` 를 받으면 저장 대기 없음 + 최근 입력 없음일 때만 본문·기준 시각 교체. 치는 중이면 «새 버전 있음» 표시만.
4. **겹치면(409) 고르게** — ①상대 버전 비교(문단 단위) ②상대 버전 불러오기(내 글은 초안 보존 `useDraftText`) ③내 글로 덮어쓰기(상대 글은 변경 기록에 남아 있음을 알림). 자동 합치기 없음(표·서명 칸 깨짐 위험).
5. **히스토리는 그대로** + 밴드2 «최근 편집: ○○ 2분 전». 토론은 문서 댓글.
- v1 밖: 실시간 커서 · 글자 단위 동시 입력 · 제안 모드 · 범위 댓글.

## 3. 나중에 A 로 갈 때 미리 정한 것
- 정본은 계속 content_json 하나. Yjs 는 편집 세션용 사본(표 `posts_yjs`), 유휴 2~5초·마지막 사람 퇴장 때 content_json 으로 내려 씀.
  content_json 을 직접 쓰는 문(AI 수정·되돌리기)은 Yjs 트랜잭션으로 바꿔야 함.
- Hocuspocus 별도 PM2 · nginx `/collab` · 접속 때 JWT + canEditPost + business_id, 연결 중 주기 재판정.
- 서명 잠금 중 업데이트 거부 · 표 문서 대상 아님 · 기존 문서는 처음 열 때 변환(일괄 이관 없음).
- 히스토리 귀속이 «한 사람» 에서 «그 사이 편집한 사람들» 로 바뀐다.

## 4. 검증 게이트 (B)
- 덮어쓰기 전에 상대 버전이 변경 기록에 반드시 한 줄(사람이 다르면 안 묶임) 실측.
- 교체(3)가 치던 글을 한 글자도 안 지움 — leavesave·drafts 카나리와 함께 · 양성 대조군(입력 중 강제 교체 → 빨간불).
- 편집 중 표시·이름이 고객 화면·공개 링크로 안 나감(소켓 payload 확인).
- 서명 잠금 409 와 충돌 고르기 창이 섞이지 않음.

## 5. B 구현 메모 (2026-10-22)
- 서버 `services/postPresence.js` 한 곳 — 방 `postedit:<id>` · 소켓 `post:presence:{join,typing,leave}` · 응답 `post:presence {post_id, users:[{userId,name,typing}]}`.
  들어오는 조건 = 워크스페이스 현직 멤버 ∧ 문서가 그 워크스페이스 것 ∧ `canEditPost`(L1 은 작성자만). 이름은 서버가 정한다(워크스페이스 표시명 → 계정 이름).
  창(소켓)마다 세고 사람 단위로 합친다 · 보기만 하는 사람은 방에 있지만 목록엔 없다 · «치는 중» = 30초 안 입력(화면이 10초에 한 번 알림, 60초마다 권한 재확인).
  워크스페이스에서 내보내면 `socketRevoke.leaveBusinessRooms` 가 같이 뺀다. (2026-08-25 첫 판은 이름을 화면이 보냈고 남의 L1 문서도 들어갈 수 있었다.)
- 화면 `components/Docs/DocCoedit.tsx` 한 벌 — 편집 중 칩(보기 메타 줄·편집 머리 줄) · «○○님도 지금 고치고 있어요» 줄 · 겹침 바([바뀐 내용 보기]=변경 기록 패널 · [최신 내용 가져오기] · [내 수정으로 덮어쓰기]) · 남겨 둔 내 글 줄([내 글 보기] 창 · [지우기]).
  남겨 둔 글은 초안 저장소 kind `doc-conflict`(이 문서·이 사람 몫 하나, 7일).
- 바로 반영(PostsPage `remoteSavedRef`): `post:updated` 신호 + 저장 대기 없음 + 저장 중/겹침 아님 + 마지막 입력 3초 넘음 + 서버 시각이 내 기준과 다를 때만. 받아 오는 사이 치기 시작하면 버린다.
- 설계와 다르게 만든 것(심플하게 — Irene): 2절 3 «치는 중이면 ‹새 버전 있음› 표시» 는 두지 않았다 — 치는 중엔 그대로 두고 다음 저장이 409 로 고르기 바를 띄운다(글은 안 잃는다).
  2절 4① «문단 단위 비교» 대신 [바뀐 내용 보기] = 변경 기록 패널(행을 누르면 그 버전 본문 미리보기).
- 서명 잠금 409(`post_locked_by_signature`)는 겹침이 아니다 — 고르기 바 대신 «서명 요청이 진행 중…» 한 줄(`SignLockedBar`)만. Fable 검증 1차 FAIL ① 로 고침.
- 남은 것: 데스크탑 탭 모드에서 같은 문서를 탭 둘(보기+편집)로 열면 소켓이 하나라 한 탭을 닫으면 다른 탭도 방에서 빠진다(드묾, 본문 누수 없음).
  서명 잠긴 문서에도 [편집] 버튼은 그대로 열린다(이번 변경 전부터).
- 남은 것: 문서 공개 범위를 좁혀(L1) 이미 방에 있는 사람 — 다음 입력 신호의 재확인(60초)·재접속 때 빠진다. 보기만 하는 사람은 재확인 신호가 없어 문서를 닫을 때까지 남의 «편집 중» 이름을 계속 받는다(본문은 안 간다).
