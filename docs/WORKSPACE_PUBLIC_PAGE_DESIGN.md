## 결론 (10줄)

1. 워크스페이스 페이지는 **이미 있다**(고객 창구 `/g/<토큰>`). 빠진 것은 ① 찾기 쉬운 자리 ② 가리기·추가 ③ 서비스 «카드» ④ 인증 없는 문의 폼 ⑤ 공개 주소·디렉터리·SEO 다섯 가지다.
2. **한 화면·한 데이터·주소 둘.** 같은 «회사 소개 화면» 을 토큰 링크(`/g/<토큰>`, 검색 안 됨)와 공개 주소(`/w/<회사주소>`, 검색 됨)가 같이 쓴다. 공개 주소는 «공개» 를 켠 워크스페이스에만 존재한다.
3. 링크는 **설정 › 새 탭 «공개 페이지»** 가 본진이고, **Q sale 머리**와 **워크스페이스 이름 메뉴**에 «우리 페이지 — 복사·QR·열기» 를 둔다.
4. 워크스페이스 정보는 자동으로 채우고, 항목마다 **보이기/가리기 스위치**, 자유 **추가 항목 8줄**, **서비스 카드 12장**(이름·설명·가격 문구·사진).
5. 문의 폼은 **인증번호 없이** 이름·이메일·내용만으로 남긴다. 저장은 **새 표 `workspace_inquiries` 1개**(스팸 격리 때문 — 근거 §5.3), Q sale «상담» 탭 맨 위 **«신규 문의»** 로 뜨고 담당자에게 알림. 한 번 눌러 고객(문의 단계)으로 등록.
6. 디렉터리는 `planq.kr/directory`(업종 16개 고정 목록 + 지역 + 검색). **첫 공개는 PlanQ 관리자 승인 후** 노출을 권고한다 — planq.kr 도메인에 스팸 페이지가 색인되면 PlanQ 전체 검색 평판이 깎인다.
7. SEO/GEO: 공개된 페이지만 운영 서버가 미리 만든 HTML(본문 포함)·schema(Organization/LocalBusiness + Service)·sitemap 에 싣는다. 끄면 **즉시** 파일·sitemap 에서 빠지고 주소는 404.
8. 뒤집는 것은 «공개 슬러그·검색 노출 금지» 와 «새 표 금지» 두 건, 범위는 **스스로 공개를 켠 + 승인된 워크스페이스**와 **문의 표 1개**로 한정한다. 켜지 않은 워크스페이스는 오늘과 한 글자도 다르지 않다.
9. 스키마: `businesses` 컬럼 5개 + 새 표 1개 + ENUM 추가 1건. 3단계(P1 찾기·꾸미기 → P2 문의 폼 → P3 공개·디렉터리·SEO), P2·P3 는 Fable 검증 뒤 배포.
10. Irene 이 정할 것 5건(§9): 페이지 구성 컨펌 · 접수 확인 메일 · 문의 저장 방식 · 노출 심사 · 노출 자격(플랜).

## 3. 주소 체계 — 한 화면 · 한 데이터 · 주소 둘

```
/g/<workspace 토큰>      토큰 링크 — 지금 그대로. 검색 안 됨(noindex). 명함·카톡·메일로 «건네는» 주소
/w/<회사주소>            공개 주소 — 공개를 켜고 승인된 워크스페이스만 존재. 검색·AI 가 읽음
/directory              PlanQ 디렉터리(전체) · /directory/<업종>  업종별 목록 · /en/… 영어
```

- **한 화면:** «안내» 본문을 `WorkspaceProfileView` 한 컴포넌트로 뽑아 `/g/` 안내 탭과 `/w/` 가 같이 쓴다. `/w/` 에는 탭이 없다 — 머리·소개·서비스·정보·문의 폼이 한 장으로 흐르고, **[상담 예약]·[채팅으로 문의]** 버튼은 살아 있는 창구 링크(`/g/<토큰>` 해당 탭)로 보낸다(예약·채팅은 인증이 필요하고 그 기계는 이미 거기 있다. 창구 링크가 없거나 예약이 꺼져 있으면 버튼 자체가 없다).
- **한 데이터:** 내용은 `businesses` 기존 칸 + `permissions.customer_entry`(§4) 하나. 직렬화는 **`services/workspacePage.js publicView(biz, {lang})` 한 함수** — 토큰 안내 탭·공개 API·미리 만든 HTML·디렉터리 카드(부분집합)가 전부 이것을 지난다. 화이트리스트(남길 것만 남긴다): id·owner·plan·permissions 원문·가린 항목은 **응답에 실리지 않는다**(화면에서만 숨기지 않는다).
- **공개 스위치(상태 한 칸)** `businesses.public_page_status`:

| 상태 | 뜻 | `/w/<주소>` | 디렉터리·sitemap | 토큰 링크 |
|---|---|---|---|---|
| `off`(기본) | 링크로만 | 404 | 없음 | 그대로 |
| `pending` | 공개 신청, 승인 대기 | 404 | 없음 | 그대로 |
| `public` | 공개 | 열림·색인 | 실림 | 그대로 |
| `blocked` | PlanQ 가 내림 | 404 | 없음(주인이 다시 못 켬) | 그대로 |

- **공개를 끄면 닫히는 것:** `/w/<주소>` 즉시 404(+ `noindex`) · 미리 만든 HTML·`.gz` 즉시 삭제 · sitemap·디렉터리·업종 목록에서 즉시 빠짐 · 그 주소의 문의 폼. **안 닫히는 것:** 토큰 링크·명함·이미 들어온 문의·채팅·예약. 검색엔진에 남은 흔적은 며칠~몇 주 걸려 사라진다(끄는 확인 창에 이 문장을 적는다).
- **자동으로 내려가는 경우:** 워크스페이스 삭제(`deleted_at`) · 노출 자격 상실(§6.5, 판정은 `services/plan.js` 한 곳) · 내용이 최소 기준 아래로 내려감(§6.3). 내려가면 owner 에게 알림 1건.
- **회사 주소(slug):** 기존 `businesses.slug` 를 쓴다(새 칸 없음). 영문 소문자·숫자·`-` 3~40자, 예약어 차단(`admin`·`api`·`planq`·`www`·`directory`·`login` 등 한 목록). 공개 화면에서 owner 가 고칠 수 있으나 **공개 중에 바꾸면 옛 주소가 끊긴다**는 확인 창(주소를 문구에 적는다). 옛 주소 자동 넘김은 만들지 않는다(P4).

## 4. 데이터 모델 — 자동 표기 · 가리기 · 추가 · 서비스

**새 표 없음(내용).** `businesses.permissions.customer_entry` JSON 을 넓힌다. 모양은 지금처럼 `routes/customer_entry.js normalizeIntro` **한 함수**(→ `services/workspacePage.js` 로 옮겨 읽기·쓰기·공개 직렬화가 같이 쓴다). 디렉터리가 **찾아야 하는 값**(상태·업종·지역)만 `businesses` 컬럼으로 둔다 — JSON 은 색인이 안 되고, 공개 여부를 JSON 에 두면 «공개인가» 판정이 쿼리마다 갈라진다.

```
permissions.customer_entry = {
  intro, intro_en,                       소개글 ≤2000자
  hidden: ['email','representative', …]  가린 자동 항목 키(아래 표의 키만 허용)
  extras: [{ label, label_en, value, value_en }]  추가 항목 ≤8줄 · label ≤30 · value ≤200 (값이 http(s) 주소면 링크)
  services: [{ id, name, name_en, summary, summary_en, price_text, price_text_en, image_url }]  ≤12장
  tags: ['브랜딩','패키지', …]            검색 키워드 ≤5개 · 각 ≤20자
  form: { enabled: true, ask_phone: false, ask_company: false }   문의 폼
  booking: { … }                         그대로
}
```
- 옛 `services: ['문자열']` 은 읽을 때 `{ name }` 으로 올린다(마이그레이션 없음, 저장 때 새 모양).
- **자동 항목과 기본값** — 값이 비어 있으면 줄 자체가 없다:

| 키 | 원천 | 기본 | 비고 |
|---|---|---|---|
| `name`·`logo`·`tagline` | `brand_name‖name` · `brand_logo_url‖logo_url` · `brand_tagline` | 보임(가릴 수 없음 — 발신자) | `_en` 칸 사용 |
| `category`·`region` | `public_category` · `public_region` | 보임 | 공개 때 필수 |
| `website` | `website` | 보임 | 바깥 링크 `rel="nofollow ugc noopener"` |
| `work_hours` | `work_hours` + `timezone` | 보임 | |
| `phone`·`address` | `phone` · `address(_en)` | 보임(지금 창구와 같음) | |
| `email` | `email` | **가림** | 문의 폼이 대신한다. 공개 색인되면 주소 수집 대상 |
| `representative`·`biz_type`(업태·종목) | `representative` · `biz_type`·`biz_item` | **가림** | 켜야 나온다 |
| 사업자번호·`legal_name`·owner 개인 정보 | — | **항목에 없음** | 공개 대상이 아니다 |

- 지금 창구는 이메일을 보여 주고 있다 → 기본값 변경으로 조용히 사라지지 않게, **이미 창구 링크가 있는 워크스페이스는 `hidden` 을 비워 둔 채 시작**(지금과 같게)하고, 새 기본값은 `customer_entry` 를 처음 저장하는 워크스페이스에만 적용한다.
- **서비스 카드**(Irene «서비스 보여주는 거 중요해»): 이름(필수 ≤40) · 한두 줄 설명(≤200) · 가격 문구(선택 ≤40, 자유 글 — «월 50만원부터»·«견적 문의») · 사진 1장(선택). 카드의 **[이 서비스 문의]** 는 문의 폼으로 내려가며 «관심 서비스» 를 미리 채운다 → Sales 에서 무엇에 대한 문의인지 바로 보인다. 사진은 **브랜드 로고와 같은 저장·서빙 길**을 쓴다(새 공개 파일 길을 만들지 않는다 — 구현 때 그 길이 무인증 서빙인지 먼저 확인).
- 편집 권한: 지금과 같다 — **owner·플랫폼 관리자만 고친다**(`assertEntryAdmin`), 멤버는 보기·주소 복사.
- `businesses` 추가 컬럼(P3): `public_page_status ENUM('off','pending','public','blocked') NOT NULL DEFAULT 'off'` · `public_category VARCHAR(32) NULL` · `public_region VARCHAR(32) NULL` · `public_published_at DATETIME NULL` · `public_block_reason VARCHAR(255) NULL` + 색인 `(public_page_status, public_category)`.

## 5. 문의 폼 → Sales «신규 문의»

### 5.1 폼
이름(필수) · 이메일(필수) · 내용(필수 10~2000자) · 관심 서비스(선택, 서비스 카드 목록) · 전화·회사명(워크스페이스가 켰을 때만) · **개인정보 수집·이용 동의(필수 체크)** — 수집 주체는 그 워크스페이스, PlanQ 는 처리 위탁. 로그인·인증번호 없음. 보낸 뒤 화면: «문의를 보냈어요. {회사}가 이메일로 답변드립니다.»

### 5.2 스팸 방어 (판정 기준 — 이 표가 계약이다. 바꾸려면 Fable `design`)

| 층 | 기준 | 결과 |
|---|---|---|
| 숨은 칸(honeypot) 채워짐 · 폼을 연 지 3초 안 제출 | 봇 | 200 으로 답하고 **저장하지 않는다** |
| IP 시간당 3 · 하루 10(랜딩 문의와 같은 값) | 넘으면 | 429 + 안내 문구 |
| 같은 이메일 → 같은 워크스페이스 하루 3 | 넘으면 | 429 |
| 워크스페이스당 하루 50건 | 넘으면 | 접수는 하되 `held` + owner 알림 1건(«문의가 몰려 보류함에 넣었어요») |
| 내용에 링크 3개 이상 · 같은 내용이 24시간 안 3개 워크스페이스 이상에 접수 | 의심 | `held`(보류함) — **알림 없음**, 상담 탭 «보류» 에서 볼 수 있다 |
| 그 외 | 정상 | `new` + 알림 |

- 지우지 않고 **보류**한다 — 기계가 틀리면 진짜 손님을 잃는다. 보류 30일 뒤 자동 삭제.
- CAPTCHA(외부 서비스)는 넣지 않는다(P4 — 실제 스팸이 위 층을 넘을 때). 무인증 LLM 판정도 넣지 않는다(비용 표면).
- 실패는 보이게: 429·검증 오류는 폼 아래 문구로(조용한 실패 금지).

### 5.3 저장 — 새 표 `workspace_inquiries` 1개 (근거)

대화방에 넣지 않는 이유: ① 무인증·미확인 입력이 `conversations`·`messages`·그림자 `users`·`guest_links` 네 표에 쌓이면 **스팸이 Q Talk 목록과 핵심 표를 더럽히고 «보류» 상태를 둘 자리가 없다** ② 미확인 연락처는 24시간 뒤 지우는 규칙(`guestContactCleanup`)과 충돌 — 문의는 답할 때까지 연락처가 남아야 한다 ③ 문의는 «건» 이다(관심 서비스·전화·상태). 고객 행을 바로 만들지 않는 이유: 미확인 이메일·스팸이 **고객 목록과 `add_prospect` 플랜 한도**를 채운다. 플랫폼 `contact_inquiries` 재사용 금지: 수신처가 PlanQ 라 섞으면 격리가 깨진다(09-24 §1.3).

```
workspace_inquiries
  id · business_id(FK, 색인) · status ENUM('new','handled','held','spam') · via ENUM('public_page','entry_link')
  name · email · phone NULL · company NULL · message TEXT · service_id NULL · service_name NULL(접수 시점 이름 사본)
  locale · ip_hash(하루 비밀 해시 — IP 원문 저장 안 함) · held_reason NULL
  client_id NULL(고객 등록 시) · email_thread_id NULL(Q mail 로 답장 시) · handled_by NULL · handled_at NULL
  created_at · updated_at        색인 (business_id, status, created_at)
```
- 모든 조회·변경은 `WHERE business_id = ?` + `checkBusinessAccess`. 감사 로그: 접수(`inquiry.receive`, 행위자 없음)·처리·삭제.
- 보존: `held`·`spam` 30일 · 고객으로 등록되지 않은 `new`·`handled` 는 1년 뒤 삭제(등록됐으면 고객 데이터로 남는다). 삭제는 기존 정리 cron 계열에 한 함수 추가.

### 5.4 Sales 에서 보이는 모양
- **Q sale › 상담 탭**: `services/saleInbox.js` `SOURCES` 에 `'inquiry'` 추가 — 소스 칩 **«신규 문의»**, 목록 맨 위 시간순, `client_id IS NULL AND email_thread_id IS NULL AND status='new'` 인 것이 «답할 차례». 행 = 이름 · 관심 서비스 · 내용 첫 줄 · 받은 시각.
- 행을 열면(기존 상담 상세 껍데기): 내용 전체 + 연락처 + 버튼 **[고객으로 등록]**(`sale_save` 의 `findExistingByContact` + `add_prospect` 한도 **같은 함수** → `clients{status:'prospect', sales_source:'web'}` + `setStage('inquiry', origin:'manual')` + 문의 내용이 고객 타임라인 첫 줄) · **[메일로 답장]**(Q mail 연결 시 작성 창에 받는 사람·인용 채움, 보낸 스레드 id 를 문의에 연결 → 그 스레드는 «사람이 올린 것» 과 같은 뜻으로 상담 유입. 미연결이면 `mailto:`) · **[처리함]** · **[스팸]**.
- 등록되거나 답장으로 스레드가 붙으면 문의 행은 «신규 문의» 목록에서 빠지고 **고객·스레드 쪽에서 이어진다**(같은 건을 두 줄로 세지 않는다).
- **배지:** Q sale 메뉴 배지 공식에 `status='new'` 미연결 문의 수를 **한 곳에서** 더한다(`.claude/rules/badges.md` 계약 — 확인 필요 = 메뉴 배지 합. 구현 전에 그 파일을 Read).
- **알림(팀):** `saleNotify.recipientsFor`(Q sale 담당 귀속, 없으면 owner) → 기존 `notifyMany`(앱·푸시·알림 설정에 따른 메일). `held` 는 알리지 않는다.
- `permissions.sales_intake`(메일 유입 모드)와 무관 — 우리 폼으로 들어온 사람은 구조상 잠재 고객이다(채팅·게스트와 같은 규칙).

### 5.5 문의자에게 가는 메일 (외부 발송 — §9 질문 2)
권고: **접수 확인 메일 1통.** 내용은 고정 문구뿐 — «{회사}에 문의가 접수되었습니다» + 그 회사 창구 링크(채팅·예약을 원하면). **문의자가 쓴 글·이름은 싣지 않는다**(남의 주소를 넣어 우리 서버로 임의 글을 보내는 통로가 되지 않게). 같은 주소로 하루 1통(워크스페이스 무관), `held`·봇 판정에는 보내지 않는다. 발신 이름은 «{회사} (PlanQ)», 회신 주소는 워크스페이스 `email`(있을 때).

## 6. PlanQ 디렉터리

### 6.1 주소·구성
`/directory`(전체) · `/directory/<업종키>` · 영어 `/en/directory…`. 랜딩 상단 메뉴와 바닥글에 «회사 찾기 / Find a company» 한 줄. 구성은 §7 와이어 ③.

### 6.2 업종 — **고정 목록 16개**(키는 영문, 라벨 ko/en)
`biz_type`·`biz_item` 은 쓰지 않는다 — 세금계산서용 자유 글(«서비스업»·«도소매»)이라 고객이 찾는 말이 아니고 목록 페이지를 만들 수 없다(고르는 화면에서 참고로만 보여 준다).

디자인·브랜딩 `design` / 마케팅·광고 `marketing` / 개발·IT `development` / 영상·사진 `media` / 경영·컨설팅 `consulting` / 세무·회계 `accounting` / 법무·노무·특허 `legal` / 번역·통역 `translation` / 교육·코칭 `education` / 건축·인테리어 `interior` / 제조·유통 `manufacturing` / 행사·기획 `events` / 부동산 `realestate` / 의료·헬스케어 `healthcare` / 생활·뷰티 서비스 `lifestyle` / 기타 `other`

업종 1개(필수) + 검색 키워드 5개(자유) + 지역(시·도 17 + «전국/온라인», 선택). 목록은 `services/workspacePage.js CATEGORIES` 한 곳 + i18n. 워크스페이스가 새 업종을 만들지 못한다(목록 페이지가 흩어진다) — 부족하면 PlanQ 가 목록을 늘린다.

### 6.3 공개 최소 기준(얇은 페이지·빈 페이지 방지) — 못 채우면 스위치가 **비활성 + 이유**
이름 · 한 줄 소개 · 소개글 100자 이상 · 서비스 1개 이상 · 업종 · 문의 받을 길 1개 이상(문의 폼 켜짐 또는 전화) · owner 이메일 인증 완료.

### 6.4 심사·신고·내리기 (§9 질문 4)
- 권고: **첫 공개는 승인제.** owner 가 공개를 켜면 `pending` → 플랫폼 관리자 > «공개 페이지» 화면(대기·공개·내림 목록, [승인] [돌려보내기+사유] [내리기+사유]) → `public`. 승인 뒤 내용 수정은 **바로 반영**(다시 심사하지 않는다 — 대신 관리자 화면에 «최근 고친 순» 정렬, 바깥 링크는 전부 `nofollow ugc`).
- 신고: 모든 공개 페이지 바닥 «이 페이지 신고» → 사유 선택 + 한 줄 → `contact_inquiries(kind='report')` → 플랫폼 관리자 알림.
- 내리기: `blocked` + 사유 → owner 알림. `blocked` 는 owner 가 다시 못 켠다(관리자가 풀어야 한다).
- 정렬: 기본 «최근 활동순»(`public_published_at`/수정 시각) — 유료 상위 노출·후기·별점은 만들지 않는다(P4, 가짜 평판 위험).

### 6.5 노출 자격 (§9 질문 5)
- **페이지·토큰 링크·문의 폼 = 모든 플랜.** 디렉터리 공개만 자격을 둔다. 권고: **유료 플랜 + 체험 중**. 체험이 끝나 무료가 되면 디렉터리·`/w/` 는 내려가고(알림) 토큰 링크는 남는다. 판정은 `planEngine.can(businessId, 'public_listing')` 한 곳.

### 6.6 검색
서버 검색(`q`): 이름·한 줄 소개·소개글·서비스 이름/설명·키워드에 부분 일치 + 업종·지역 필터. 지금 규모에서는 `public_page_status='public'` 행만 읽어 서버에서 거른다(전문 검색 색인은 공개 500곳을 넘을 때). 결과 없음 화면: «아직 없어요 — 다른 업종 보기». 검색어가 붙은 주소는 `noindex`.

## 8. SEO · GEO

`.claude/rules/seo-landing.md` 의 «워크스페이스는 대상 아니다» 를 **«공개를 켜고 승인된 워크스페이스 페이지와 디렉터리는 대상»** 으로 고친다(P3 구현 커밋에서 같이). 생성 원칙은 기존 그대로 — **운영 서버가 운영 DB 로** 만든다(dev 시험 페이지가 운영에 새지 않는다), `.gz` 같이 쓰기, 자기가 만든 파일만 지운다.

| 항목 | 설계 |
|---|---|
| 미리 만든 HTML | `services/seoArtifacts.js` 에 «공개 워크스페이스» 생성기 추가 — `/w/<slug>/index.html`, `/directory/index.html`, `/directory/<업종>/index.html`(+`/en/`). 본문은 `publicView` 와 **같은 값**을 `<main id="seo-prerender">` 에(소개·서비스·회사 정보·업종). 사용자 글은 전부 HTML 이스케이프 |
| 생성 시점 | 기존(배포 직후·서버 시작·매일 0시) + **상태가 바뀔 때 즉시**(승인·끔·내림·주소 변경) + 내용 저장 뒤 10분 묶음. 끔·내림은 그 요청 안에서 파일·`.gz` 삭제까지 끝낸다(다음 0시까지 남으면 «껐는데 보인다») |
| title·description | `{이름} — {업종} · {지역} \| PlanQ` · 한 줄 소개 + 소개글 앞부분 ≤155자 · canonical · og(이미지 = 로고, 없으면 기존 `routes/og.js` 생성) |
| schema(JSON-LD) | 주소를 보이면 `LocalBusiness`(address·telephone·openingHoursSpecification ← `work_hours`), 아니면 `Organization` · `hasOfferCatalog` → 서비스마다 `Service`(name·description, 가격은 숫자가 아니라 넣지 않는다) · `BreadcrumbList`(회사 찾기 › 업종 › 회사) · 디렉터리는 `CollectionPage` + `ItemList`. **가린 항목은 schema 에도 없다.** 별점·후기 schema 금지(없는 평판) |
| sitemap | `public` 인 `/w/…` 와 디렉터리·업종 페이지(+lastmod). 끄면 즉시 제거 |
| noindex 경계 | `/g/*` 그대로 noindex · `off/pending/blocked` 는 404 · 검색어·페이지 번호가 붙은 주소는 `noindex,follow` + canonical 은 기본 주소 · **공개 회사 3곳 미만 업종 목록은 noindex + sitemap 제외**(얇은 페이지) · dev 도메인은 전부 noindex |
| robots.txt | `/w/`·`/directory` 는 막지 않는다. AI 크롤러도 막지 않는다(GEO 가 목적 — 공개 확인 창에 «AI 검색이 읽습니다» 고지). `/g/`·`/public/` 학습 차단 줄은 그대로 |
| llms.txt | «회사 찾기» 절 추가 — `/directory` 와 업종 목록 주소·한 줄 설명(회사별 줄은 넣지 않는다, sitemap 이 맡는다) |
| GEO 본문 | 회사 페이지 첫 문단을 «{이름}은(는) {지역}의 {업종} 회사로, {서비스1}·{서비스2}를 제공합니다.» 한 문장으로 자동 조립(사실만, 워크스페이스 값에서) — AI 가 인용하기 쉬운 형태. 업종 페이지 머리에 업종 정의 두 문장 + 회사 수 |
| 영어 | `/en/w/<slug>` 는 **영어 소개글이 있을 때만** 만들고 hreflang 쌍. `/en/directory` 는 전체를 싣되 영어 값 없으면 한국어 값 |
| `seo-pages.json` | `/directory` 한 줄(정적 문구) 추가. 회사·업종 페이지는 인사이트 글처럼 DB 에서 온다 |

**i18n:** 화면 문구 새 네임스페이스 `wspage`(공개 페이지·디렉터리 — 무로그인이라 가볍게) + `settings`(편집 화면) + `qsale`(신규 문의) + `landing`(메뉴 한 줄), ko/en 동시. 내용은 `_en` 칸(선택) — 비면 한국어로 보인다. 화면 언어 = 방문자 언어, 접수 확인 메일 = 폼을 보낸 화면 언어(`locale` 저장).

## 9. Irene 에게 묻는 결정 (5건)

1. **페이지 구성(§7 와이어 ①②③ + 업종 16개 목록)을 이대로 진행할까요?** — 예 / 고칠 곳 지적. 권고: 예.
2. **문의를 남긴 사람에게 «접수되었습니다» 확인 메일 1통을 보낼까요?** — (가) 보낸다: 손님이 안심하고, 창구 링크로 채팅·예약을 이어갈 수 있다. 인증 안 된 주소로 나가는 메일이라 고정 문구만·주소당 하루 1통으로 묶는다 / (나) 안 보낸다: 발송 위험 0, 손님은 화면 문구만 본다. 권고: **(가)**.
3. **문의가 오면 어디에 쌓을까요?** — (가) Q sale 상담 탭 «신규 문의» 에 쌓고 한 번 눌러 고객 등록: 스팸이 고객 목록·요금제 고객 수 한도를 채우지 않는다 / (나) 오는 즉시 고객 목록에 «문의» 단계로 자동 등록: 누를 일이 없지만 스팸·오타 주소도 고객이 된다. 권고: **(가)**.
4. **«회사 찾기» 노출을 PlanQ 가 먼저 확인할까요?** — (가) 첫 공개만 관리자 승인(보통 1영업일): planq.kr 에 스팸·부적절 페이지가 검색에 잡히는 것을 막는다. 지금 규모(운영 워크스페이스 8곳 안팎)에서는 부담이 작다 / (나) 켜면 바로 공개 + 신고·사후 내리기: 빠르지만 스팸 가입이 planq.kr 검색 평판을 깎을 수 있다. 권고: **(가)**, 공개 회사가 늘면 (나)로 전환 검토.
5. **누가 «회사 찾기» 에 올라갈 수 있나요?** — (가) 유료 플랜 + 체험 중: 체험이 끝나 무료가 되면 내려간다(링크·문의 폼은 유지) / (나) 무료 포함 전부: 디렉터리가 빨리 차지만 스팸 가입 동기가 생긴다 / (다) 유료만: 가장 깨끗하지만 처음에 디렉터리가 빈다. 권고: **(가)**.

작은 것은 정했다(다시 묻지 않는다): 주소 이름 `/w/`·`/directory` · 이메일·대표자 기본 가림 · 서비스 12장·추가 항목 8줄 · AI 크롤러 허용 · 별점·후기·유료 상위 노출 없음 · CAPTCHA 없이 시작 · 편집은 owner 만.

### 하지 말 것
- 공개를 켜지 않은 워크스페이스의 **어떤 값도** 무인증 응답·HTML·sitemap 에 싣지 않는다(slug 포함). 판정은 `public_page_status==='public'` **한 술어**(`isPubliclyListed(biz)` — 삭제·자격·전체 스위치 포함)이고 API·생성기·디렉터리가 같이 부른다.
- 공개 직렬화를 라우트마다 손으로 쓰지 않는다 — `publicView` 한 함수, 화이트리스트.
- 문의로 그림자 User·대화방·고객 행을 자동으로 만들지 않는다. 문의 폼에서 프로젝트·청구 어떤 것도 열리지 않는다.
- 디렉터리에서 여러 회사에 한꺼번에 문의하는 기능을 만들지 않는다.
- dev 에서 SEO 생성물을 만들어 배포에 싣지 않는다(기존 규칙).
- 스팸 기준(§5.2)·공개 최소 기준(§6.3)을 구현 중에 임의로 바꾸지 않는다.
- 시험 데이터는 ws 6·7(시험 워크스페이스)에만, 이름 앞 `[확인용]`.
