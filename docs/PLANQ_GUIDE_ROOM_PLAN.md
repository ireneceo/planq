## 2. 플랫폼 관리자 쪽에서 보면

### 2-1. 워크스페이스 상세 «여정» 탭 (`/admin/businesses/:id`)
- **맨 위 요약**: 지금 적응 단계(1~5) · 마지막 접속 · 앱 설치 · 알림 켬 · 메일/캘린더/AI 앱 연결 · 체험 남은 날 · 막힘 신호 개수
- **멤버별 줄**: 사람마다 단계·개인 설정(알림·캘린더·앱·AI 앱)·마지막 접속
- **메뉴 지도**: 열어 본 메뉴(처음·마지막·횟수) / 한 번도 안 연 메뉴
- **시간줄**: 가입 → 첫 업무 → 첫 대화 → 첫 멤버 수락 → 첫 고객 초대 → … (사건만. 제목·본문 없음)
- **막힘 신호** 목록 + [안내방 열기]

### 2-2. 안내방 받은편지함 (새 관리자 메뉴)
- 워크스페이스별 방 목록 · 안 읽음 · «사람 연결 요청»·막힘 신호 붙은 방이 위로
- 방을 열면 왼쪽 대화, 오른쪽 여정 요약(2-1 축소판)
- 메시지마다 [피드백으로]·[문의로] 저장(관리자가 대신 옮기기)
- 제안 메시지 **초안함**: 규칙이 걸린 안내가 쌓임 → [보내기]·[고쳐서 보내기]·[건너뛰기]
- 고객이 [사람에게 묻기] 를 누르거나 Cue 가 답을 못 하면 기존 «확인 필요»(`/admin/inbox`) 에도 한 줄

### 2-3. 고객 여정 통계 (새 관리자 메뉴)
- 가입 → 단계 1~5 깔때기 · 단계마다 평균 걸린 날 · **가장 많이 멈추는 칸**
- 안 쓰이는 메뉴 · 막힘 유형별 수(설정 실패·오류·무접속·같은 질문 반복)
- 안내 메시지 효과 — 규칙별 «보낸 뒤 24/72시간 안에 그 일을 했나» 비율
- **콘텐츠 보완 후보** — 막힘 많은 메뉴 × 그 메뉴 위키 글 유무 · 안내방·Q helper 의 못 답한 질문 묶음(기존 위키 초안 흐름)

**관리자가 보는 것은 «사용 모양» 까지다.** 업무 제목·대화 본문·문서 내용은 여정·통계에 나오지 않는다.
관리자가 내용을 볼 수 있는 대화는 **그 워크스페이스의 안내방 하나**뿐(다른 Q talk 방은 지금처럼 못 본다).

## 4. 덩어리별 기획

### A. 발자국 (어느 메뉴까지 봤나)
- 남기는 것: 사람 × 워크스페이스 × **메뉴 키**(`qtask`, `qtalk`, `settings.mail` …) 의 처음·마지막 연 시각·횟수. **주소 전체·검색어·항목 번호는 남기지 않는다**(문서 제목·«나만 보기» 가 섞여 샌다).
- 표 `usage_footprints` — 덮어쓰는 집계형(행이 날마다 늘지 않음). 날짜별 추이는 밤에 `usage_daily` 로 묶기.
- 화면: 주소가 바뀔 때 메뉴 키만 모아 30초마다 한 번 보냄(사용자당 분당 제한).
- 막힘·멈춤 신호(기록에서 계산): ① 가입 후 첫 행동까지 시간·가입 당일만 쓰고 끊김 ② 단계 한 칸 N일 정체 ③ 같은 설정 화면 여러 번 + 완료 0
  ④ 화면 오류·권한 거절·메일 인증 실패 직후 ⑤ «도움이 안 됐어요»·같은 질문 반복.
- 개인정보: 처리방침에 «자동 수집: 접속 기록·기기 정보» 가 이미 있다(`locales/ko/legal.json`). 메뉴 단위면 그 범위 안 — 문구를 «서비스 이용 기록(열어 본 메뉴)» 으로 구체화할지 설계 때 확인.

### B. 여정·통계 화면 — 2절

### C. PlanQ 안내방
- 워크스페이스가 생기면 하나. 이미 있는 워크스페이스는 첫 접속 때 만든다(운영 일괄 쓰기 없이).
- 참여: (결정 1) 권고 = 대표·관리자 기본, 멤버는 스스로 «들어가기». 고객(Client)·게스트는 **절대 안 보임**.
- Cue 답: Q helper 두뇌 + 사용 상태 문맥. 워크스페이스 업무·대화·문서는 안 읽음. 비용(결정 2).
- 관리자 말: «PlanQ 팀 · 이름» 표시, 말한 뒤 일정 시간 Cue 멈춤.
- **엔진(Fable 설계로 판정)**:
  - 1안: 기존 대화(`conversations`)에 새 종류 `platform` — 실시간·읽음·푸시·첨부·앱 화면을 그대로 씀. 대신 이 방을 워크스페이스 검색·내보내기·AI 앱 도구·휴지통·
    워크스페이스 Cue 자동답변·고객 화면·통계에서 **모두 빼야 한다**(지금 `channel_type` 을 읽는 곳 백엔드 23파일·화면 9파일 전수), 관리자 출입 판정을 `access_scope` 한 곳에.
  - 2안: 플랫폼 소유 별도 표(`support_threads`/`support_messages`) — 경계가 깨끗(새는 길이 처음부터 없음), 대신 채팅 화면·실시간·푸시를 새로 만든다.
  - 기획 쪽 생각: 1안이 빠르지만 «빼야 할 곳» 하나만 놓쳐도 플랫폼 대화가 워크스페이스 검색·AI 앱에 섞인다. 2안은 화면을 Q talk 부품으로 다시 쓰면 새로 만들 양이 생각보다 작다. → Fable 판정.

### D. 제안 메시지
- AI 가 마음대로 쓰지 않는다 — **조건 → ko/en 틀 → 바로 가기 버튼** 규칙표. Cue 는 이름·남은 일 정도만 채움(1절 표가 처음 묶음 8개).
- 처음엔 «관리자 검토 후 보내기»(결정 4) → 규칙별 반응률을 보고 하나씩 «자동» 으로.
- 크론은 살아 있는 워크스페이스만(`workspaceAlive` 술어 — 기존 가드).
- 알림(결정 3): 권고 = 사람 답·피드백 답 소식은 푸시, Cue 제안은 앱 안 배지만. 메일로는 안 보냄.

### E. 대화 → 피드백·문의 → 답 알림
- Cue 가 «요청 같다 / 질문 같다» 고 보면 카드로 묻고 **고객이 눌러야 저장**(결정 5). 자동 저장은 «내 말이 왜 저기 접수됐지» 가 된다.
- 저장: `feedback_items`(kind feedback|inquiry, 출처 «안내방», 원 메시지 연결) → 기존 관리자 피드백·AI 원인 조사·단계 흐름 그대로.
- 답이 오거나 단계가 바뀌면(진행대기·완료) 안내방에 한 줄 + 기존 알림.
- 기존 피드백 창에서 쓴 것도 안내방에 같은 줄을 남김(권고 — 1:1 소통이 한 곳에 모인다).
- «요청인가 질문인가» 를 가르는 기준은 분류 기준이라 Fable 설계에서 정한다.

### F. 콘텐츠 보완
- 안내방 질문도 `help_question_logs` 에 출처 «안내방» 으로 쌓아 기존 위키 초안 흐름에 태움 + 2-3 «보완 후보» 목록.

## 7. 왜 Fable 설계가 필요한가 (PlanQ «되돌리기 어려운 것»)
멀티테넌트 격리(플랫폼 관리자가 워크스페이스 방에 들어감) · 인증/권한(`access_scope` 출입 판정) · 외부 발송 트리거(먼저 말 걸기·푸시) ·
AI 쓰기 표면(Cue 가 먼저 쓰는 메시지·피드백 저장) · 분류 기준(요청/질문 가르기·막힘 판정) · 운영 DB 새 표/ENUM.
→ Irene 결정 뒤 **설계 1회**(엔진 1안/2안 · 출입 판정 · 분류 기준 · 발송 상한) + 단계 3·5 완료 검증.

## 8. 확인 방법 (구현 뒤)
- 여정 탭: `/admin/businesses` → ws 6 «여정» [as=admin] — owner 로 앱 세션·메일 연결을 만들면 숫자가 바뀌는지
- 발자국: owner(ws 6)로 Q task·Q mail 연 뒤 행 2개 · 다른 워크스페이스에 안 섞임(tenant 스위트)
- 안내방: owner 질문 → Cue 답(워크스페이스 Cue 사용량 불변) · admin 답 → owner 화면 1초 안 반영 · member·client 보임/403 ·
  워크스페이스 검색·내보내기·AI 앱 응답에 이 방 0건(음성 대조군)
- 피드백 다리: [남기기] → `feedback_items`(source=support_room) → 관리자 답 → 안내방 한 줄
- 제안: 시험 워크스페이스 시계를 당겨 규칙 걸림 → 초안 1건 → 보내기 → 재발송 0 · 하루 1건 상한
- 가드: `npm run build` · `guard-invariants` · `health-check` · `e2e --suite tenant`

## 9. Irene 결정 (구현 전 · 번호대로)
1. 안내방은 **워크스페이스에 하나**(대표·관리자 기본, 멤버는 들어오기)? 사람마다 1:1? — 권고: 워크스페이스 하나
2. Cue 비용은 **플랫폼 부담**(워크스페이스 Cue 사용량에서 안 뺌)? — 권고: 플랫폼 부담(Q helper 와 같게)
3. 알림: 사람 답·피드백 답 소식은 **푸시**, Cue 제안은 **앱 안 배지만**? — 권고: 그렇게
4. 제안 메시지는 처음에 **관리자 검토 후 보내기**? — 권고: 예, 반응 보고 규칙별 자동
5. 대화 → 피드백/문의는 **고객이 눌러야 저장**? — 권고: 예
