# PlanQ AI 협업 프로토콜

## 목적

PlanQ 저장소에서 Claude Code와 Codex를 함께 사용하되, 역할과 책임을 분리하고 작업 경계를 명확히 한다. 두 AI는 자동으로 서로를 호출하거나 위임하지 않으며, 한 번에 한 AI만 파일을 편집한다.

## 역할 분리

### Fable

- 기존 코드 조사
- 개발 기획과 요구사항 해석
- 설계 및 아키텍처 판단
- 복잡한 검증과 최종 판단

### Opus

- Fable이 정한 설계의 핵심 구현
- 설계 범위를 벗어난 아키텍처·주요 데이터 모델·주요 서비스 변경은 임의로 시작하지 않는다.

### Codex

- 보조 개발자 역할
- 명확한 단순·반복 작업 수행
- 사용자가 지정한 명령 실행
- 장시간 검사 또는 빌드 대기
- 자신이 만든 변경의 자기 검증

Codex는 기존 코드 조사, 개발 기획, 설계, 아키텍처 결정, 주요 클래스·서비스·DB 변경을 스스로 시작하지 않는다. 작업 지시가 모호하거나 선택지가 있으면 임의로 결정하지 말고 사용자에게 구체적인 지시를 요청한다.

## 독립 운영 원칙

- Claude Code와 Codex는 서로 자동 위임하거나 연결하지 않는다.
- 사용자가 Codex를 사용하는 세션에서는 Codex가 자신이 수행한 작업을 직접 검증한다.
- 한 번에 한 AI만 파일을 편집한다. 다른 AI의 작업이 진행 중이면 편집하지 않는다.
- 작업 전후에 `git status`와 `git diff`를 확인한다.
- 다른 AI의 미커밋 변경을 덮어쓰거나 정리하지 않는다. 충돌 가능성이 있으면 작업을 중지하고 사용자에게 알린다.
- 기록과 보고에는 실제 작업 주체를 표시한다.

## 작업 기록 표기

문서·커밋·완료 보고에서 작업 주체를 다음처럼 표시한다.

```text
[Claude Code] 기존 코드 조사·기획·설계·복잡한 검증·최종 판단
[Opus] Fable 설계 기반 핵심 구현
[Codex] 지정된 단순 작업·명령 실행·대기·자기 검증
[공동 검토] 사용자 지시 또는 양쪽 결과를 함께 대조한 내용
```

## 변경 경계

Codex 세션에서는 지시받은 파일과 작업만 수정한다. 지시가 없는 소스 코드, DB, 배포 설정, 다른 프로젝트 파일은 읽거나 수정하지 않는다. 특히 PlanQ 외부 경로와 Purple POS 파일·DB·프로세스는 작업 대상에서 제외한다.

## 완료 조건

- 작업 전후 Git 상태와 diff가 기록되어야 한다.
- 각 변경에는 실제 작업 주체와 수행 내용을 기록한다.
- Codex가 변경한 내용은 Codex가 지정된 검증 명령을 직접 실행하고 결과를 기록한다.
- 설계 판단, 복잡한 검증, 최종 승인은 Fable 또는 사용자 지시에 따른다.
