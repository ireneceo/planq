# 팀 적응 단계 — 설계 (2026-10-09)

> Irene: *"플랜큐는 기능이 너무 많아. 팀이 적응하는데 필요한 단계별 안내가 필요해. 정리해서 도움말에 넣고
> 랜딩페이지에도 처음 시작하는 팀에게 나눠서 적응하는 효과적인 방안 정리할래? 워크스페이스에도 적응단계 안내하면서
> 하나 하나 사용하게 하면 어때? 예를 들면 처음 가장 효과적인 건 업무 관리 업무요청이야. 서로의 업무를 공유하고
> 요청하는 거 말로하기도 있고 챗지피티랑 클로드에서도 가능해. 프로젝트랑 연결해서 업무등록. 그리고 채팅과 이메일로
> 소통하는 거. 여기까지가 2단계인거지. 이런 식으로 정란 어때??"*

## 0. 지금 있는 것 (실측)
- 대시보드·설정 최상단 `components/Onboarding/OnboardingChecklist` «업무 효율 높이기» — 서버 `services/onboarding.js` 가
  실제 데이터로 완료를 판정한다(체크박스 없음). 묶음 둘:
  - `workspace`(owner/admin): 고객 초대 → 대화 시작 → 업무 만들기 → 메일 연결 ← **고객 업무 순서**라 Irene 이 말한 순서(업무 → 소통)와 반대다.
  - `me`(멤버 전원): 알림 · 캘린더 · 앱 설치 · AI 앱 연결 — 기기·계정 설정.
- Q위키 «시작하기» 칸: 워크스페이스 만들기·팀 초대·고객 초대 등 **기능 사용법**뿐. «무엇부터 익히나» 글은 없다.
- 랜딩: 홈·기능·요금·서비스·진단·소개 — «처음 시작하는 팀의 적응 순서» 는 없다.

## 1. 단계 (정본 — 세 표면이 같은 다섯 단계를 쓴다)

PlanQ 의 주 업무는 **업무관리 + 내부소통**이다(포지셔닝 정본). 그래서 1·2단계가 그 둘이고, 고객·청구는 마지막이다.
한 단계가 팀의 습관이 된 뒤 다음으로 간다 — 한꺼번에 다 켜면 아무것도 습관이 되지 않는다.

| 단계 | 이름 | 무엇이 습관이 되나 | 해 보는 것(완료 판정 = 실제 데이터, 이 워크스페이스·나 기준) |
|---|---|---|---|
| 1 | 업무 공유·요청 | 할 일을 말이 아니라 업무로 남기고, 서로 요청한다 | 팀원 초대(owner/admin) · 내 업무 등록 · 동료에게 업무 요청(담당자 ≠ 나) · 프로젝트에 연결해 등록 · 말하듯 쓰거나 ChatGPT/Claude 로 등록 |
| 2 | 대화·메일로 소통 | 업무 이야기를 메신저 대신 업무 옆에서 | 팀 대화방에서 메시지 보내기 · 메일 연결(owner/admin = 회사 메일 계정 / 멤버 = 볼 수 있는 메일함이 있으면) |
| 3 | 일정·회의 | 회의가 기록과 업무로 끝난다 | 일정 만들기 · Q note 로 회의 기록(녹음·업로드) |
| 4 | 자료·문서 | «그 파일 어디 있지» 가 사라진다 | 파일 올리기 · 문서 쓰기 |
| 5 | 고객과 함께 | 고객 요청·청구까지 같은 흐름에 | 고객 초대(owner/admin) · 고객 대화방에서 메시지 · 청구서 만들기(owner/admin) |

- **기기·계정 설정(알림·캘린더·앱·AI 앱)은 단계가 아니라 옆 묶음 «내 설정»** 으로 그대로 둔다 — 사람마다 한 번 하는 일이고 습관이 아니다.
- «말로 하기» = AI 업무 추가(문장으로 쓰면 업무로 나눠 줌) · ChatGPT/Claude 연결 후 말로 시키기 · Q note 회의에서 업무 뽑기.
  판정: 내가 만든 업무 중 `created_via ∈ ('agent','cue','ai_draft')` 가 있으면 완료. AI 업무 추가 확정 경로가 지금은
  `created_via` 를 비워 두므로 `'ai_draft'` 를 넣는다(표시 전용 컬럼 — 권한·전이 무관, 화면 배지는 cue/agent 만 그려 새 값은 보이지 않는다).

## 2. 워크스페이스 화면 — «하나씩»
- **새 카드를 만들지 않는다.** 같은 `OnboardingChecklist` 의 `workspace` 묶음 자리를 **단계 묶음**으로 바꾼다(대시보드·설정 같은 컴포넌트 한 벌).
- 카드 머리: «팀 적응 단계» · 단계 점 1~5(끝난 단계 ✓, 지금 단계 강조) · 접기 · 다시 보지 않기.
- 본문: **지금 단계 하나만** 펼친다 — 단계 이름 + 한 줄 «왜» + 해 볼 것 줄들(기존 줄 모양 그대로: 표시 · 이름 · 왜 · [열기] [사용법]).
  지금 단계 = 안 끝난 줄이 있는 첫 단계. 다른 점을 누르면 그 단계를 들여다볼 수 있다(잠그지 않는다 — 이미 쓰는 팀을 막지 않는다).
- 아래에 «내 설정» 묶음(기존 `me`) 그대로.
- 단계가 다 끝나면 단계 묶음은 사라진다(기존 규칙). 닫기는 사람 단위(`business_members.onboarding_dismissed_at`) — 단계는 팀원 각자의 습관이라 멤버도 본다.
- 하위 호환: 응답 최상위 `steps/total/done_count` 와 `groups[workspace]` 는 옛 번들을 위해 그대로 둔다. 새 필드 `stages`.
- 서버는 key·done·단계 번호만 말한다. 문구는 i18n(`dashboard.json onboarding.stage.*`).

## 3. 도움말 (Q위키)
- 새 글 `team-adoption-stages` «팀이 PlanQ 에 적응하는 5단계» — 시작하기 칸 맨 앞. 단계마다: 무엇이 습관이 되나 · 해 볼 것 · 팀에 권하는 기간 · 관련 사용법 글 이름.
- 카드의 단계 머리에 [안내 글] → 이 글(askCue wiki). 인사이트 피드에도 싣는다(BLOG_MAP guide).

## 4. 랜딩
- 새 공개 페이지 `/start` «처음 시작하는 팀을 위한 5단계» — 같은 다섯 단계(문구는 landing.json `start.*`), 각 단계 1~2주 권장, 끝에 가입 CTA.
- `seo-pages.json` 에 한 줄(본문 sections = 같은 키) · 푸터 PRODUCT 에 링크 · 기능 페이지 끝에 링크 하나.
- 홈 첫 문장·정의 문장은 건드리지 않는다(포지셔닝은 Irene 정본).

## 5. 하지 않는 것
- 단계 잠금(다음 메뉴 숨기기) — 이미 쓰는 팀·고객 업무 위주 팀을 막는다. 안내만 한다.
- 단계 완료를 저장하는 컬럼 — 데이터로 매번 판정(지우면 다시 안 끝난 것이 된다).
- 새 DB 컬럼·마이그레이션 없음.

## 6. 검증
- API: 새 계정(owner·member)로 각 줄 행동 → `GET /onboarding` 의 그 줄 done 이 바뀌는지(전후 대조) · 다른 워크스페이스 데이터로는 안 켜지는지.
- 화면: 대시보드 3폭(390·820·1440) — 지금 단계만 펼침 · 점 클릭 · 버튼 이동 · 보이는가(elementFromPoint).
- 랜딩 `/start` 3폭 + 생성 HTML 에 본문 · 위키 글 렌더.
- 가드: build · guard-invariants(i18n·parity) · health-check.
