# 설문 기능 검토 의견 (#460) — 2026-10-07

> Irene #460: *"우리 설문기능도 추가하는 거 복잡해? 검토만 하고 의견 좀 줘. 설문 > 관리 > 통계확인 이런거 복잡한지."*
> [Opus] 조사·의견. 구현하지 않았다(검토 요청).

## 한 줄 결론

**복잡하지 않다 — 새 시스템이 아니라 이미 있는 «표 문서»(Q docs `kind='table'`)에 «설문으로 받기» 보기를 하나 얹으면 된다.**
문항 = 표의 칸, 응답 1건 = 표의 행 1줄, 통계 = 칸별 집계. 새 테이블도 거의 필요 없다.
**단 하나 무거운 결정은 «누가 응답하나»** — 외부(로그인 없는) 응답을 받으면 무인증 공개 표면이 생겨 설계·Fable 게이트 대상이 된다.

## 이미 있는 것 (그대로 쓴다)

| 설문에 필요한 것 | 이미 있는 것 |
|---|---|
| 문항 종류 | 표 칸 타입 — 단답(text) · 장문(longtext) · 숫자 · 날짜 · 예/아니오(checkbox) · 객관식(select) · 복수선택(multi_select) · 이메일 · 전화 · URL (`models/QRecord.js columns`) |
| 응답 저장 | 표의 행(`q_record_rows.values`) + 행 단위 이력(`q_record_audits`) |
| 관리(목록·수정·삭제·내보내기) | 표 문서 화면 그대로 — 응답을 표로 보고 고치고 지운다 |
| 공개 범위 | 문서의 L1~L4 · 프로젝트 연결 (표 읽기 = 문서 읽기와 같은 술어 `canViewRecord`) |
| 공개 링크 인프라 | 문서·청구서·서명의 공유 링크(토큰·비밀번호·만료·`usePublicRevalidate`) · 상담 예약의 «무인증이지만 좁은 문» 선례(`routes/guest_booking.js`) |
| 차트 | 보고서·통계 화면의 막대·원형 차트 컴포넌트 |
| AI 요약 | Cue — 장문 응답 «요약해 줘» 는 Q info/문서 요약과 같은 길 |

## 새로 만들 것

| 단계 | 내용 | 규모 | 게이트 |
|---|---|---|---|
| ① 응답 화면 | 표의 칸을 위→아래 문항으로 그리는 «설문 보기»(필수 여부·설명·선택지). 제출 = 행 추가 | 중 (프론트 2~3파일) | 자체 검증 |
| ② 통계 화면 | 객관식·복수선택·예/아니오 = 비율 막대 · 숫자 = 평균/분포 · 날짜 = 추이 · 장문 = 목록(+Cue 요약 선택) | 중 | 자체 검증 |
| ③ 내부 응답 | 워크스페이스 멤버·로그인 고객이 링크로 응답 — 기존 인증으로 끝 | 소 | 자체 검증 |
| ④ **외부(무로그인) 응답** | 공개 링크 → 제출만 되는 좁은 문. 레이트리밋·중복 응답 방지·응답 마감·개인정보 수집 동의 문구·`secret` 칸 금지 | 중~대 | **R=1 — 공개 라우트 추가, Fable 설계 게이트** |
| ⑤ 응답 알림 | 새 응답이 오면 만든 사람에게 앱 알림(메일은 끔) | 소 | 자체 검증 |

①②③⑤ 만이면 **기존 표 위에서 끝나는 중간 규모**다. 무겁게 만드는 것은 ④ 뿐이다.

## 일부러 하지 않을 것 (제안)

- **별도 «설문» 테이블·메뉴를 새로 만들지 않는다** — 표와 설문이 따로 서면 응답을 표처럼 다루는 기능(정렬·필터·내보내기·이력)을 두 번 만들게 된다(CLAUDE.md «새로 만들지 않는다»).
- 분기 문항(답에 따라 다음 질문이 바뀜)·점수 계산·익명 보장 같은 «설문 전문 도구» 기능은 첫 판에서 뺀다 — 쓰임을 보고 더한다.

## Irene 이 정해야 할 것

1. **누가 응답하나** — (가) 내부·로그인 고객만 / (나) 외부 누구나(공개 링크).
   권고: **(가)로 먼저.** 고객 만족도·팀 설문은 대개 (가)로 충분하고, (나)는 공개 표면이라 설계 게이트를 따로 거친다.
2. **어디에 두나** — Q docs 표 문서의 «설문으로 받기»(권고) / 별도 메뉴.
3. **요금제** — 모든 요금제 / 상위 요금제만(외부 응답 수 제한 등).
