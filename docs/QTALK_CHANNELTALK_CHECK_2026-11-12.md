# 채널톡 쓰는 고객사 기준 — Q talk 채팅 불편 점검 (2026-11-12 · [Opus] · Fable 안 씀)

> Irene: *"채널톡 쓰는 고객사가 우리 거 같이 쓸건데 이거 제대로 사용하게 불편한 채팅영역 기능 없는지 체크해줘."*
> 정찰 계획 `.claude/plans/qmwd8qfbe.md`(HEAD 9420b372) 를 코드로 다시 확인했다. 그 뒤 커밋(6255de4f)은 Q talk 은 사람 고르기만 건드려 결론이 같다.
> 코드에 채널톡 연동은 **없다** — 이번 점검은 «채널톡 상담 화면에 익숙한 사람이 Q talk 을 쓸 때 빠졌다고 느낄 것» 대조다.

## 이 방에서 고친 것 (화면·작은 서버 확인 — 자체 검증)
| # | 빠졌던 것 | 고침 |
|---|---|---|
| 1 | **답장(인용)이 없었다** — 서버는 `reply_to_message_id` 를 받는데 화면이 늘 비워 보냈다. 여러 요청이 섞이면 어느 말에 답했는지 모름 | 도구줄 «답장» → 입력창 위 «OO 님에게 답장» 띠(✕·Esc 로 취소) → 말풍선 위 원문 한 줄(누르면 원문으로 이동). `pages/QTalk/ReplyQuote.tsx` |
| 1-b | 서버가 답장 대상 id 를 **확인 없이** 저장했다(다른 방 메시지 id 도 들어감) | 같은 대화·안 지운 메시지만 저장, 아니면 비움 — `services/messageReply.resolveReplyTo` |
| 2 | **안 읽은 대화만 보기**가 없었다 | 대화 목록 검색 아래 [전체 \| 안 읽음 N] — 지금 연 방은 읽는 순간 0 이 돼도 남긴다 |

원문은 **화면에 이미 보이는 메시지 목록에서만** 찾는다 — 서버가 원문을 따로 싣지 않으므로 고객에게 안 보이는 내부 메시지·지운 메시지가 인용으로 새지 않는다(못 찾으면 «원문을 볼 수 없어요»).
