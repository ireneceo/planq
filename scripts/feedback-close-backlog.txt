# 밀린 장부 — "이미 배포됐는데 pending 인 채로 남은 피드백" 번호.
#
# 평소에는 이 파일을 쓸 일이 없다 — 커밋 메시지에 아래 트레일러 한 줄을 넣으면 배포가 알아서 닫는다:
#
#     Feedback-Closes: 213, 220
#
#   ★ 본문에 `#213` 이라고 **인용만** 한 것은 닫히지 않는다. 일부러 그렇게 했다 —
#     2026-08-21 실측으로, 본문 `#숫자` 를 긁었더니 근거로 인용한 업무 번호(#123 #167 #180 #274)와
#     주석 속 옛 사례(#258 #280 #286)까지 잡혀 **고치지도 않은 신고가 닫힐 뻔했다.**
#
# 왜 이 파일이 필요한가:
#   deploy-planq.sh 의 close_feedback 은 **이번 배포 범위의 커밋 메시지**에서 번호를 뽑는다.
#   그런데 이미 배포가 끝난 옛 커밋(예: 6b3f4590 · 41158147)에 들어 있던 번호는 그 범위에
#   영영 안 들어온다 — 그래서 자동으로는 못 닫는다. 그 잔여분을 여기 적어 같이 실어 보낸다.
#
# 규칙:
#   · 한 줄에 번호 하나. `#` 뒤는 주석.
#   · **운영에 실제로 도달했음을 확인한 것만** 적는다(소스에 있다 ≠ 배포됐다).
#     확인법: ssh 87.106.78.146 'grep -rl "<문자열>" /opt/planq/frontend-build/assets/*.js'
#   · 닫기 자체의 안전장치는 close-deployed-feedback.js 에 있다 — 답글 없는 건은 안 닫고,
#     이미 done 이면 건너뛴다(멱등). 그래서 닫힌 뒤에도 줄을 남겨 둬도 해가 없다.
#   · 다 닫힌 줄은 정리해도 된다(선택).

# ── 2026-08-21 확인분 — 2026-09-03 배포에서 **전부 닫힘 확인, 줄 정리** ──
#   213 220 222 232 257 260 287 — 운영 feedback_items 에서 done 확인 후 지웠다.
#
#   ★ 지운 이유: 이 파일은 **매 배포마다 다시 실려 나간다.** 닫기 자체는 멱등이라 해가 없지만,
#     개발 현황의 "닫은 신고" 에 **같은 번호가 배포마다 반복 기록**돼 네 배포가 전부 같은 7건을
#     닫은 것처럼 보였다(2026-09-03 Irene 이 발견: "배포리스트가 왜 다 같은 버전이야?" 를
#     보다가 같이 나왔다). 기록 쪽은 deploy-planq.sh 가 실제로 닫힌 번호만 적도록 고쳤고,
#     이 파일도 **닫힌 줄은 그때그때 지우는 것**을 규칙으로 한다.
