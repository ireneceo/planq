## ★ 배포는 «마지막 커밋의 깨끗한 사본» 에서 나간다 (2026-10-12)

> Irene 2026-10-11: *"배포를 하면 모든 작업 일시정지하고 점검 후 배포해야지. 진행중인 거 있으면 그건 빼고."*

- `deploy-planq.sh` 가 시작할 때 `scripts/make-deploy-snapshot.sh` 로 **HEAD 커밋의 사본**을 임시 폴더에 만들고,
  가드·사본 검사·프론트 빌드·rsync·마이그레이션·릴리즈노트·장부·개발 현황·`.last-deployed-commit` 을 **전부 그 커밋으로** 한다.
  작업 폴더(`/opt/planq`)는 읽기만 한다 — stash·checkout·커밋하지 않는다. dev 화면 빌드(`dev-frontend-build`)도 안 건드린다.
- **작업 폴더의 미커밋 = 다른 방의 진행 중 일이다. 커밋하지 않고 빼고 배포한다.** 스크립트가 «미커밋 N개 — 이번 배포에서 뺀다» 로 보여 준다.
  ⛔ 배포 방은 **남의 작업 파일을 커밋하지 않는다.** `git add -A`·`git commit -a`·stash 금지.
- **배포 방이 만든 산출물만** 경로를 지정해 커밋한다 — `git commit -m "…" -- <경로…>`:
  `docs/dev-status/next.json` · `docs/release-notes/v*.json` · `scripts/feedback-close-backlog.txt` · 버전 올린 `package.json` 2개 ·
  `.claude/session-state.md` · `DEVELOPMENT_PLAN.md`. 배포 스크립트는 **커밋된** 기록을 읽으므로 이 커밋은 **배포 전에** 한다
  (안 하면 스크립트가 «배포 기록이 커밋 안 됨» 경고를 내고 옛 기록이 나간다).
- **절차도 그 커밋 것이다 (2026-10-16).** 스크립트는 시작할 때 HEAD 를 한 번 읽어 고정하고, **그 커밋의 `deploy-planq.sh`·`make-deploy-snapshot.sh`
  를 임시 폴더(`/tmp/planq-deploy-self.*`)에 꺼내 그것으로 다시 실행**한다. 다른 방이 이 스크립트에 넣은 **미커밋 마이그 슬롯 줄은 불리지 않는다**
  («배포 스크립트 미커밋 — 이번 배포에서 뺀다» 경고만). 예전(10-12 C1)엔 이때 `--routine` 이 멈춰 정기 점검이 매번 막혔다.
  시작 뒤 생긴 커밋은 이번 배포에 안 실린다(다음 배포). 손으로 HEAD 사본을 꺼내 돌릴 필요가 없다.
  ★ 커밋 판으로 도는 것은 이 두 스크립트뿐이다 — 게이트의 `health-check.js` 는 살아 있는 dev 서버를 때리므로 종전대로 작업 폴더 것이 돈다.
- 사본에만 붙는 것: 프론트 `.env`(빌드 환경값) · `node_modules` 링크 · 백엔드 `.env`(검사용 — rsync 는 `.env` 를 보내지 않는다).
- 운영 rsync 는 **보호 목록**으로 운영 쪽 파일을 지킨다 — `secrets/`(앱 푸시 키) · `backups/` · `.claude/` · `.last-deployed-commit` +
  작업 폴더에서 git 이 무시하는 경로 전부. 사본에는 그것들이 없어 보호가 없으면 `--delete` 가 운영 푸시 키를 지운다(rsync -n 실측).
- 사본 백엔드는 운영 재시작 전까지 한 번도 실행되지 않는다(health-check 는 작업 폴더 코드를 때린다) — 그래서
  `scripts/check-deploy-snapshot.js`(문법 오류·커밋에 없는 파일 require)가 `--skip-gates` 여도 돈다.
- 자동 저장은 작업 브랜치가 아니라 `refs/autosave/*` 에 쌓인다(`scripts/claude-autosave.sh`) — 진행 중 일이 HEAD 에 섞이지 않는다.
  배포할 커밋이 `wip: auto-save` 면 `--auto`/`--routine` 은 멈춘다.

## 0단계 — 버전을 **먼저** 정한다 (2026-09-03 수정)

**버전 올리기는 배포 *전*이다.** 개발 현황의 `version` 은 배포 시점의 `dev-backend/package.json`
에서 읽는다(`deploy-planq.sh` `MY_VER`). 그래서 배포 뒤에 올리면 **한 칸씩 밀린다** —
방금 나간 배포는 옛 버전으로 기록되고, 새 버전은 내용이 다른 **다음** 배포에 붙는다.
릴리즈노트 v1.48.7 이 `1.48.6` 이라고 적힌 행의 내용을 설명하는 상태가 된다(2026-09-03 실제로 그랬다).

배포를 시작하기 전에 Irene 에게 묻는다:

```
"버전 올릴까요? (현재: x.y.z → 다음 patch x.y.{z+1})"
```

- **올린다면 배포 전에** `dev-backend/package.json` · `dev-frontend/package.json` 을 같이 올리고
  커밋한다. 릴리즈노트 `docs/release-notes/v{버전}.json` 도 이때 쓴다(발행은 배포 뒤 4단계).
- **안 올린다면** 그대로 둔다. 같은 버전이 여러 배포에 반복되는 것은 **정상**이다 —
  버전은 며칠에 한 번 오르고 배포는 하루 여러 번이라, 배포를 구별하는 것은 `commit_to` 다.

### ★ 배포가 도는 동안은 무거운 것을 띄우지 않는다 (2026-10-23 — Irene «배포중이었는데 혼자 멈췄어 … 배포가 너무 힘든데?»)

10-22 배포 빌드가 세 번 «Terminated»(서버 메모리 보호 earlyoom)로 죽었다 — 빌드의 tsc 가 4.7GB 까지 커지는데(7.9GB 서버)
그 위에 밤 검사·배포 방 자신의 dev 빌드·Fable 검증이 겹쳤다. 빌드 게이트(heavy-task-gate)는 **시작할 때만** 막아서
**나중에 뜬 작업이 배포 빌드를 죽인다.** 그래서 배포 스크립트가 도는 동안(`scripts/deploy-busy.sh` 가 exit 0):
- **배포 방은 스크립트가 끝날 때까지 다른 일을 띄우지 않는다** — dev 빌드(`npm run build`) · Fable 검증(`/fable-검증`·Agent) ·
  브라우저 시험(`scripts/e2e/run.js`) · health-check 외 검사 스크립트 · 다른 솔루션 빌드. 배포를 백그라운드로 돌렸으면 그 완료 알림을 기다린다.
  배포 뒤 확인(3단계)·Fable 사후 검증은 스크립트가 **끝난 다음**에 한다.
- **다른 방도 같다** — 이 규칙은 기계가 같이 막는다: dev `npm run build` 의 prebuild 가 배포가 끝날 때까지 기다리고(배포 자신의 빌드는
  `PLANQ_DEPLOY_PIN` 으로 건너뜀), e2e 러너·전체 검사는 **스위트마다**, 밤 순찰은 시작 전에 기다린다(최대 90분, 넘으면 멈추거나 건너뜀).
  기다리는 중이면 `[deploy-busy] … 기다린다` 한 줄이 보인다 — 우회(표시 파일 지우기·SKIP_MEMGATE)하지 않는다.
- 배포가 남기는 표시는 `logs/deploy-running.pid`(pid 가 살아 있고 deploy-planq.sh 일 때만 «배포 중»). 같은 표시로 **배포 두 개가 겹치는 것도 막는다**.
- 한계: 이미 돌고 있는 한 스위트(밤 순찰 한 판 등)는 도중에 멈추지 않는다 — 그래서 밤 검사를 정기 점검 배포(00:15 MYT)와 겹치지 않는 시각으로 옮겼다.

스크립트 진행 단계 (~3-5분 · 메모리 게이트를 기다리면 더 길다):

0. make_snapshot — HEAD 커밋의 깨끗한 사본을 `/tmp/planq-deploy-src.*` 에 만든다(끝나면 지운다). 미커밋 목록은 «뺀다» 로 표시만
1. preflight (dev 헬스 + SSH 도달 + **코드 게이트**: health-check(작업 폴더 dev 서버) · 불변식 가드(**사본**) · 사본 검사(문법·require))
   ★ 2026-09-09 신설 — `health-check` 와 `guard-invariants` 를 **여기서 하드 게이트로** 돌린다.
     하나라도 실패하면 배포가 그 자리에서 멈춘다(exit 1). 여태 배포 스크립트에는 품질 게이트가
     하나도 없어서 사람이 기억해야만 돌았다 — **게이트에 안 붙은 가드는 없는 가드**다.
     느린 실브라우저 카나리는 넣지 않는다(배포마다 수 분이 붙으면 `--skip-gates` 가 습관이 되고,
     그러면 게이트가 다시 0개가 된다).
2. show_changes (변경 파일 목록 + 사용자 확인 1회)
3. backup (운영 backend/frontend-build/q-note → /opt/planq/backups/{TIMESTAMP})
4. sync_backend (rsync **사본** dev-backend → 운영, .env·secrets·backups 등 보호 목록)
5. sync_frontend (**사본 안에서** npm run build + rsync → 운영 frontend-build. dev 화면 빌드는 안 건드림)
6. sync_qnote (rsync **사본** q-note → 운영, --skip-qnote 옵션 가능)
7. install_deps (운영서버 npm ci --production)
8. sync_database (운영서버 node sync-database.js)
9. restart_server (PM2 reload planq-prod-backend / planq-prod-qnote)
10. reload_nginx (운영서버 sudo systemctl reload nginx — sudo 없으면 skip + Irene 안내)
11. verify (https://planq.kr/api/health 200 + 27/27 헬스체크 항목)
12. update_record (이번에 **보낸 커밋**(DEPLOY_COMMIT) 기록 — 배포 중 HEAD 가 움직여도 어긋나지 않는다)

**플래그**:
- `--auto` — 확인 프롬프트 생략 (검증된 재배포 / 핫픽스)
- `--routine` — 정기 점검 배포. `--auto` + 릴리즈노트(발행·초안) 단계 건너뜀
- `--dry-run` — 미리보기만
- `--skip-build` — 백엔드만 (긴급 hotfix). 프론트는 빌드도 rsync 도 안 한다 — 운영 프론트는 직전 배포 그대로
  (예전엔 작업 폴더의 기존 빌드를 올려 미커밋 화면 변경이 섞일 수 있었다)
- `--skip-qnote` — Q Note Python 서비스 제외
- `--skip-gates` — 코드 게이트 건너뜀. **장애 대응 hotfix 전용** — 평소에 쓰면 게이트가 없는 것과 같다

### 장부 닫기 — `close_feedback()`
커밋 메시지에 **명시적 트레일러**를 적어야 닫힌다. 인용은 자유롭게 하되, 닫으려면 의도적으로 적는다.

```
Feedback-Closes: 213, 220        ← 이 배포로 해결된 신고
Feedback-Keeps-Open: 378         ← 앞선 커밋이 닫으려 했으나 부분 해결이라 철회
```

- **답글이 없는 건은 닫지 않는다** — 닫힌 이유를 모르는 사용자에게는 무시당한 것과 같다.
- 옛 커밋의 잔여분은 `scripts/feedback-close-backlog.txt` 에 번호를 적으면 다음 배포에 실린다.

### 개발 현황 발행 — `publish_dev_status()`
플랫폼 관리자 > **개발 현황** 화면에 이번 배포가 남는다. 배포 전에 **`docs/dev-status/next.json`** 을 쓴다.

```bash
# 내용 검사 (커밋 전에도 된다)
cd /opt/planq/dev-backend && node scripts/publish-dev-status.js ../docs/dev-status/next.json --dry-run
```

- 섹션 11종: `working_on` `in_progress` `completed` `behavior_changes` `issues`
  `blocked_on_human` `migrations` `check_areas` `backlog` `tooling_health` `undeployed`
- **기계가 아는 값은 적지 않는다** — 커밋 범위·배포 시각·롤백 경로·닫은 신고·스키마 변경 여부는
  배포 스크립트가 `--meta` 로 주입한다. 사람이 또 적으면 반드시 갈라진다.
- `completed[].verified` 는 `fable_pass` | `opus_only` | `none` 셋뿐이다. 다른 값은 발행이 거부된다.
- 본문에 HTML 태그를 넣지 않는다 — 이 화면은 텍스트로만 렌더한다(관리자 화면 저장형 XSS 차단).

━━━━━━━━━━━━━━━━━━
