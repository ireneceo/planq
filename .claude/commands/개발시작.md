### 1-B단계: 운영서버 피드백 확인 (매번 — 건너뛰기 금지)

> Irene 2026-10-07: *"개발시작 스킬에 운영서버 피드백을 항상 체크하게 해줘."*

운영 DB 원문을 **직접** 읽는다(요약본·session-state 의 목록을 믿지 않는다 — memory `feedback_read_prod_feedback_verbatim`).
읽기 전용 조회다. 운영 DB 에 쓰지 않는다(답글은 `/개발완료` 단계).

```bash
ssh irene@87.106.78.146 "PW=\$(grep '^DB_PASSWORD=' /opt/planq/backend/.env | cut -d= -f2-); \
  mysql -h localhost -u planq_admin -p\"\$PW\" planq_prod_db --batch -e \
  \"SELECT id,parent_id,kind,category,status,created_at,page_url,title,LEFT(body,600) body, \
           (admin_response IS NOT NULL AND admin_response<>'') answered \
    FROM feedback_items WHERE status IN ('pending','reviewing') ORDER BY id;\""
```

- **새로 들어온 것**(지난 세션 이후 `created_at`)과 **답글 달렸는데 아직 열린 것**(reviewing)을 나눠 보여준다.
  `parent_id` 가 있는 행은 기존 신고의 **후속 글**이다 — 원글과 같이 읽는다.
- 신고마다 **이미 고쳐졌는지 먼저 잰다**(코드·운영 데이터) — 사흘 전에 끝난 것을 다시 고친 전례가 있다
  (memory `feedback_verify_before_refixing`).
- 4단계 안내에 **피드백 목록(번호 · 한 줄 요약 · 판단: 이미 해결/조치 필요/결정 필요)** 을 포함한다.
- 이번 세션에서 다룬 피드백 번호를 session-state.md 에 적어 둔다 — `/개발완료` 가 그 번호들에 답글을 단다.

### 1-C단계: 밤 검사 결과 확인 (매번 — 건너뛰기 금지)

> Irene 2026-10-07: *"자꾸 모바일에서도 깨지고 기능이 작동 안하는 것도 나오고. 너무 심각해."*
> 원인 하나: 매일 밤 순찰이 이틀 연속 실패(exit=1)했는데 **아무도 읽지 않았다.** 검사는 돌았고 결과는 파일에만 있었다.

매일 밤 두 가지가 돈다(dev, 쓰기 막음 · 데이터 불변):
- **순찰** 16:00 UTC(00:00 MYT) — 화면 × 5환경 + 고객 2환경 버튼 눌러보기 + 연 창 모양 (`logs/patrol/patrol-<날짜>.log`)
- **전체 검사** 순찰 직후 — 등록된 스위트 전부 (`logs/sweep/<날짜>/summary.md`)

```bash
cd /opt/planq
tail -3 logs/patrol/cron.log; f=$(ls -t logs/patrol/patrol-*.log | head -1); grep -E "^## |\[FAIL\]" "$f" | head -40
d=$(ls -td logs/sweep/20*/ | head -1); head -40 "$d/summary.md"
```

- **실패는 새 일보다 먼저 처리한다.** 판정: ①실제 결함(사용자가 만나는 것) → 고친다(UI·단일 라우트는 F=1, 자체 검증)
  ②검사기 고장(셀렉터·픽스처) → 검사기를 고치고 **양성 대조군으로** 다시 빨개지는지 확인 ③데이터 오염(카나리 잔여) → 청소 + 카나리 정리 코드.
  «하니스 탓» 으로 끄지 않는다(memory `feedback_red_check_may_be_real_bug`).
- 4단계 안내에 «밤 검사: 순찰 실패 N · 전체 검사 실패 N(스위트 이름)» 한 줄을 넣는다. 0 이면 0 이라고 적는다.
- 결과 파일이 없거나 날짜가 하루 넘게 지났으면 **그 자체가 이상**이다 — cron(`crontab -l | grep e2e`)부터 본다.
- 체계 전체: `docs/qa/UI_VERIFICATION_SYSTEM.md`

## 핵심 규칙 요약

### 절대 금지
- **운영서버 직접 수정 금지** → 배포 스크립트만 사용
- **샘플/가짜 데이터 사용 금지** → 모든 데이터는 DB에서 API로
- **alert(), toast.success() 금지**
- **POS 관련 파일/DB/PM2 절대 건드리지 않기**

### 개발 워크플로우
```bash
# 1. 개발서버에서 작업
/opt/planq/dev-backend/
/opt/planq/dev-frontend/

# 2. DB 스키마 변경 시
cd /opt/planq/dev-backend && node sync-database.js
pm2 restart planq-dev-backend

# 3. 프론트엔드 빌드 (반드시 run_in_background: true)
cd /opt/planq/dev-frontend && npm run build

# 4. 백엔드 변경 시
pm2 restart planq-dev-backend
```

### API 응답 형식
```javascript
// 성공
res.json({ success: true, data: result });

// 실패
res.status(400).json({ success: false, message: 'Error message' });
```
