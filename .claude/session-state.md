## 이번 세션에서 배운 것 (재발 방지)

1. **★ 컨트롤러/플래그를 `return null` 컴포넌트에 두면 cleanup 이 안 돈다.** 언마운트가 아니므로 effect cleanup 이
   실행되지 않아 body 플래그가 남는다. **렌더를 접는 술어를 effect 조건과 deps 에 같이 넣어야** 정합이 선다.
2. **★ 죽은 코드는 지워야 한다 — 고치면 "고친 줄 알고" 넘어간다.** `UpdateBanner` 의 겹침을 같이 고쳤지만
   렌더처가 0 이라 아무 효과가 없었다. Fable 이 그 커밋을 PASS 로 뭉개지 않고 "미검증(무해 확증)" 으로 남긴 것이 옳았다.
3. **★ 같은 목록을 두 곳에 적으면 반드시 갈라진다.** health-check 의 `--help` 카테고리 목록이 그랬다
   (동작하는 필터가 문서상 없는 것처럼 보였다). 고칠 때 **손으로 채우지 말고 정본 1벌 + fail-closed 검사**로.
4. **★ 하니스 좌표 문제로 보이는 것이 실사용자 결함일 수 있다.** "FAB 중심이 다른 버튼에 덮여 클릭이 빗나갔다"는
   관찰의 진짜 정체는 **설치 배너가 도크를 덮어 5/5 페이지에서 도달 0** 이었다. 하니스가 우회하면 결함이 숨는다.
5. **★ FK 를 붙이는 순서가 곧 안전성이다.** `FOREIGN_KEY_CHECKS=0` 상태의 `ADD FOREIGN KEY` 는 기존 행을
   검증하지 않는다 — 고아 정리보다 sync 가 먼저 돌면 "고아 + FK 공존" 최악 상태가 조용히 만들어진다.
6. **★ 분기 없는 어휘는 가짜 커버리지다.** 관찰성 사유에 코드 분기가 없는 `sync_disabled` 를 넣을 뻔했다 —
   "사유가 다 있다" 는 착시가 이 설계가 잡으려던 침묵을 스스로 재생산한다. 어휘는 코드 분기와 1:1 대조.
7. **검증 중에는 소스를 건드리지 말 것.** Fable 하니스는 미커밋 워킹트리를 `git diff` 로 읽는다.
8. **미커밋 상태에 `git checkout --` 금지.** 반증 실험 원복은 `cp` 백업본에서.
