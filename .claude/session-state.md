## 오늘 배운 것

- **fail-closed 는 값을 잘못 읽어도 똑같이 조용하다.** 파생 토큰이 `created_at` 을 못 읽어
  (Sequelize `underscored` 는 **컬럼** 이름만 바꾼다 — 속성은 `createdAt`) null 이 됐고
  알림이 0통이었는데 에러가 없었다. 게다가 "키 없으면 null" 검사는 **이미 null 이라 통과**였다.
  같은 이유로 보관기간 cron 이 아무것도 안 지우면서 "0건 정리" 를 냈다. **양성 대조군 없이는 못 잡는다.**
- **스테일 인스턴스의 `update()` 는 조용히 건너뛴다.** HTTP 로 회수한 뒤 그 인스턴스로
  `update({revoked_at:null})` 하면 dataValues 가 이미 null 이라 "변경 없음" 으로 UPDATE 가
  안 나간다. 복구가 실패했는데 아무 말이 없다. `reload()` 먼저.
- **본문을 똑같이 맞춰 놓고 시간으로 새면 열거를 막은 것이 아니다.** 신규 주소만 bcrypt 때문에
  400ms 느렸다.
- **지우는 목록을 두 곳에 적으면 한쪽이 덜 지운다.** 삭제 라우트와 보관기간 cron 을 함수 하나로.
- **부르는 곳을 세는 방식은 새 경로에서 빠진다.** "라우트 두 곳" 이라고 믿었는데 여덟 곳이었다.
