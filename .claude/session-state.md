## 이번 세션에서 배운 것 (반복 방지)

- **한 방향만 반증하면 반대 방향이 뚫린다.** 이미지 토큰이 일반 인증에서 통했다 —
  "일반 토큰이 이미지 자리에서 거부되는가" 만 쟀고 그 반대를 안 쟀다. 열쇠를 갈라 고쳤다.
- **주석이 거짓말하면 다음 사람이 확인하지 않는다.** "드래그아웃과 같은 술어" 라고 써놓고
  실제로는 갈라져 있어 남의 개인 파일이 메일로 나갈 수 있었다.
- **백엔드에만 넣고 화면 목록에 빠뜨리면 도달할 수 없다** (시리즈 중요도).
- **sync-database 는 모델에 없는 컬럼을 DROP 한다.** 마이그레이션 주석에 그렇게 써놓고 당했다.
- **가드는 스냅샷을 본다** — 컬럼을 만들면 `node scripts/dump-schema.js` 를 같이 떠야 한다.
- **`curl -I` 는 HEAD 다** — GET 게이트를 재면 거짓 실패가 난다.
- **동시 빌드는 SIGTERM 으로 죽는다** — 같은 서버에서 POS 가 Playwright 를 띄운다.
  배포 전 `free -m` 확인. 백엔드 전용 커밋이면 `--skip-build`.
- **배포 exit 0 을 믿지 말 것** — 143(SIGTERM)로 죽어도 알림은 완료로 보인다.
  착지 3점(헬스·PM2 uptime·청크 시각)으로 확인.
- **API 를 직접 부르는 테스트는 "화면이 그 API 를 안 부르는 것" 을 못 잡는다.**
  토글 6/6 실호출 PASS 를 내고 배포 직전이었는데, 실브라우저로 눌러 보니 PUT 0건이었다.
  같은 이유로 **운영 점검 모드가 눌러도 안 먹는 상태**로 살아 있었다.
- **가드의 판정 술어를 세 번 조였고 매번 앞 단계가 거짓 PASS 를 냈다.**
  "PUT 이 났는가"(엉뚱한 컨트롤도 통과) → "그 필드인가"(옛 값도 통과) → "그 값인가".
- **가드가 원복하는 자원은 경합한다.** 요청이 보이자마자 원복하면 화면의 저장이 나중에 처리돼
  **dev 가 점검 모드로 남은 채 EXIT 0.** 응답까지 기다리고, 끝에서 상태를 스냅샷과 대조한다.
- **하니스가 바뀌면 반증을 다시 한다.** 판정 기준을 고쳐 놓고 옛 반증 결과를 재사용하면 그건 반증이 아니다.
- **`&&` 사슬 앞의 grep 이 실패하면 뒤가 통째로 안 돈다.** `grep "<Wrapper $type"` 의 `$` 가
  행끝 앵커로 읽혀 exit 1 → **빌드가 아예 안 돌았는데** 결과가 나온 것처럼 보였다.
  로그가 `BUILD_EXIT=1` 한 줄뿐인 것으로 알아챘다 — **빈 로그는 "실패" 가 아니라 "안 돌았음"** 일 수 있다.
- **`2>/dev/null` 이 "상태를 못 읽음" 을 "정상 출력" 으로 보이게 했다.** 운영 상태 조회 스크립트에서.
- **프로세스를 죽일 땐 PID 로.** `node -e` 패턴으로 훑었다가 POS 프로세스를 건드렸다(무해했으나 실수).
