## 이번 세션에서 배운 것 (재발 방지)

1. **★ 진단 도구가 틀리면 서사 전체가 거짓이 된다.** `calendars.get` 은 `calendar.events` 스코프로
   호출할 수 없는 메서드다. 그걸로 찔러 "lua 연결 사망·scope 위조" 라는 잘못된 결론을 냈고
   Irene 에게 그대로 보고했다. **API 를 진단에 쓸 땐 그 메서드가 해당 스코프에서 허용되는지부터 확인할 것.**
2. **★ "완료" 표시된 것이 반쪽일 수 있다.** #242 는 `done` 인데 ②가 미구현이었다.
   장부(feedback status)와 실제를 **커밋 이력 + 운영 스키마 + 실호출** 3중으로 대조해야 진짜 상태가 나온다.
3. **★ 워크스페이스 링크는 `user_id` 가 항상 NULL.** 그걸 actor 로 쓰면 권한 판정이 무조건 실패해
   기능이 조용히 죽는다(운영 링크 8건 중 6건이 워크스페이스였다). Fable 이 잡았다.
4. **★ 원격 파이프는 종료코드를 가린다.** `ssh HOST 'false | tail'` → exit 0.
   로컬 `set -euo pipefail` 은 원격 셸에 미치지 않는다 — 명령 문자열 안에 `set -o pipefail;` 을 넣어야 한다.
5. **★ underscored 모델 인스턴스엔 `created_at` 이 없다** (camelCase `createdAt`). `new Date(undefined)` = NaN
   → 비교가 항상 거짓 → 가드/분기가 통째로 죽는데 문법검사·가드는 전부 통과한다.
6. **★ 치유·복구 로직은 쓰기 경로다 — 동시성 먼저 생각할 것.** 치유를 grace 앞에 두니 병렬 10발이
   서로의 후속을 폐기하며 경합해 200 이 10/10 → 5/10 으로 붕괴했다.
7. **★ 가드를 통과시키려 주석을 줄이는 건 가드를 속이는 것.** god-file 래칫이 깨졌을 때
   절출(정석)로 풀어야 한다 — 이번엔 `services/authTokens.js`.
8. **운영에 쓰기를 만들지 않고도 검증할 수 있다.** 운영 코드 == dev 코드를 md5 로 증명한 뒤
   dev 에서 실호출하면 된다. 운영엔 실고객 13명·5워크스페이스가 있다.
