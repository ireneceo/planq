## 완료된 작업 (이번 세션)

운영 피드백 **신규 15건 중 12건** 처리. 세션 내내 반복된 주제는 **"만들어졌는데 화면에 도달하지 못한 것"**.

### 1. Cue 가 워크스페이스를 못 보고 있었다 (#291·#292·#294) — `b700ddf6`
`authenticateToken` 이 `req.user` 에 `active_business_id` 를 안 실어 **항상 undefined** → 가입 순
첫 워크스페이스 고정. 전환해도 옛 워크스페이스를 답했다(실측: active=7 인데 biz6 응답).
읽기만이 아니다 — `execute-action` **쓰기**도 그리로 갔고, `/help` 플랜 쿼터 게이트는
**한 번도 작동한 적이 없었다**(bizId undefined 라 통째로 스킵).
컨텍스트에 고객이 아예 없었고(고객 9명인데 "정보 없음"), 회사 이름조차 없어 소개를 지어냈다.

**보안 — 수신자(audience) 절단 신설.** Cue 답변은 고객 대화방으로도 나가는데, 수동 트리거가
"마지막 고객 메시지" 라면서 **발화자를 안 가려** 직원 권한 컨텍스트가 고객행 답변 재료가 되고
있었다(기존 결함). 기본값을 좁은 쪽(client_facing)에 둬 인자를 빠뜨린 호출처가 자동으로 안전.

### 2. Q helper 3건 (#293·#295·#296) — `48ce68e3`
복귀 탭이 Q위키로 하드코딩(대화가 남은 건 정상, **탭이 틀렸다**) · 탭 부제 문구가
**ko/en 양쪽에 이미 있는데 어디서도 안 쓰이고** 있었다 · 입력창 rows=2 고정.

### 3. 탭 뱃지가 저마다 다른 것을 세고 있었다 (#297) — `d15c9053`
오늘만 목록 크기, 이번 주는 액션 수, 전체는 **Q Talk 추출 후보 수**. 오늘 ⊆ 이번 주인데 15 vs 1.
#237 로 오늘 탭이 들어올 때 기존 탭의 잣대를 같이 훑지 않아 생긴 어긋남.

### 4. "이전 후보 보기" 가 아무 일도 안 했다 (#298) — `08c26f28`
effect deps 에 상태가 빠졌고 **eslint 예외로 경고까지 꺼져** 있었다. 게다가 고쳐도 신고자
화면엔 hidden 0건이라 무반응 — 정의를 "지나간 후보 전부" 로 넓혔다(처리분은 읽기 전용 카드).
서버에서 status=all 로 받아와도 **패널이 다시 pending 으로 거르던 한 겹**이 더 있었다.

### 5. 440px 팝아웃 상세 (#290) — `461ed3a9`
리스트는 팝아웃 전용 경량 뷰인데 상세는 메인과 같은 2,598줄 드로어.
Fable 이 **죽은 56px 띠**(없는 헤더 자리)를 찾아냈다. AI 요약은 만들지 않았다 —
관리 필드를 접으니 원래 내용이 위로 올라왔다(신규 데이터 0, 비용 0).

### 6. 팝아웃 핀 — 세 번째 신고 (#286) — `1a9c8481`
원하는 형태("팝아웃 우측 상단 핀 → 그 창이 고정")가 **웹에서 원리적으로 불가능**함을 스펙으로 확인:
PiP 창은 명세상 opener 문서보다 오래 못 산다 → 팝아웃이 자기 PiP 를 열고 사라질 수 없다(옛 홀더 2창의 필연).
데스크탑 네이티브면 가능하나 이 기능 하나로는 권하지 않음. iOS 는 네이티브여도 불가.
→ 창 1개 불변식을 **양방향**으로, 핀이 아예 없던 헤더에 **방법을 안내하는 핀**을 되살렸다.

### 7. 진척 그래프가 "다 없던" 것 (#288) — `9745f9d7`
데이터는 매일 쌓인다(8,184행). 그래프가 **기간 내 증가분만** 그리는데 지난주 162건 중 변한 건
10건, 신고 시점은 월요일이라 하루치 — 통합 보고서 12섹션 중 11개가 빔. **기간 초에는 구조적으로 빈다.**
"증가 0" 과 "데이터 없음" 을 갈랐고, 그 과정에서 **가용시간 공식이 3벌로 갈라져 화면 30h·보고서 40h**
인 것을 `services/memberCapacity.js` 로 통합(정본 = 사용자가 이미 보던 화면 공식).

## ⚠️ 이번 세션에서 배운 것 (재발 방지)

1. **★ Fable 게이트 FAIL 3회 — 전부 배포하면 안 되는 것이었다.**
   ① 유출 방지 술어가 **고객 본인 청구 조회라는 정상 기능을 같이 죽였다**(설계 재판정 구속 정정)
   ② #286 이 **"새로고침한 창에서만 되는"** 상태 — effect 순서 레이스로 처음 연 창엔 구독이 영영 없었다
   ③ 진척 기준선이 **한 번도 렌더된 적 없는 죽은 코드** — recharts `ifOverflow` 기본값이 discard
2. **★ 새 것을 만들면 기존 것의 잣대를 전수로 훑어야 한다.** 오늘 탭(#237)이 목록 크기를 세는 동안
   나머지 탭은 액션 수를 세고 있었다. #290 도 같은 계열(리스트만 경량화하고 상세는 안 함).
3. **★ 같은 값의 공식이 여러 벌이면 반드시 갈라진다.** 가용시간 3벌(화면 30h / 보고서 40h),
   주간 집합 3벌(#223 전례). **통합이 기능 추가의 선행 조건**이다.
4. **★ 이미 있는데 안 쓰이는 것**이 반복해서 나왔다 — 탭 부제 문구(ko/en 존재, 미사용),
   capacity 기준선(컴포넌트는 준비됨, 값 미전달). 만들기 전에 **있는지부터 본다**.
5. **★ 사용자에게 플랫폼 한계를 통보하기 전에 그 주장부터 반증시킨다.** #286 은 내가 "웹에선
   불가능" 이라고 답할 뻔했고, Fable 이 스펙 원문으로 확인해 준 뒤에야 근거가 생겼다.
6. **★ 문구는 동작이 바뀌면 거짓이 된다.** #286 안내문("자동으로 닫혀요")이 결함 때문에 거짓이었고,
   고친 뒤에도 녹음 예외를 안 적어 반쪽 거짓이었다.
