### ⑤ "KB에 저장" — 이름으로 뭘 하는지 모른다 (**반복 신고**)

> Irene: "KB에 저장이라는 거 뭔지 모른다고 전에 말했는데 아직도 이름도 그대로네.
> 뭘하는 거고 이름으로 알게 하고 작동도 제대로 하게 해야지."

**★ 전에 말했는데 그대로 = 도달 못 한 수정**(memory `feedback_fixed_but_unreachable`).

**실측 — 실제로 하는 일** (`TaskDetailDrawer.tsx:521` `saveBodyToKb`):
결과물 본문(`body`)의 HTML 을 텍스트로 바꿔 `POST /api/businesses/:id/kb/documents` 로
보낸다. 카테고리는 `'업무 결과물'` 고정. **목적은 Cue 가 답변에 쓰게 하는 것**이다
(`kbSaveHint` 에 그렇게 적혀 있지만 힌트를 열어야 보인다).

**문제 3가지:**
1. **이름** — "KB" 는 내부 약어다. `ko/qtask.json:660 kbSave`. 사용자 말로 바꿔야 한다
   (예: "Cue 가 참고하게 저장" / "지식으로 저장").
2. **되돌릴 수 없다** — `kbSaved` 가 되면 버튼이 잠기고, 잘못 저장한 것을 화면에서 못 지운다.
3. **조용히 실패한다** — `catch { /* ignore */ }`. 실패해도 사용자는 모른다
   (memory `feedback_apifetch_no_throw_silent_save`).

→ 이름·되돌리기·실패 표시 셋을 같이 고쳐야 "작동도 제대로" 가 된다.

**저장하면 안 되는 값 둘**이 섞여 있었다.

| 섞여 있던 값 | 증상 |
|---|---|
| 부팅 경로 | 주소로 들어온 모든 경로가 마지막 탭으로 튕김(알림·공유·딥링크 전부) |

**PWA 는 로그인된 채 앱 경로로 부팅**해 `tab` 모드로 들어간다.
→ **데스크탑 앱 검증은 "로그인 후 앱 경로 전체 재로드" 조건에서 잰다.**

## 오늘 배운 것

- **저장소에 넣으면 안 되는 값이 상태에 섞이면 조용히 되살아난다.** 부팅 경로와 실행 모드가 그랬다.
- **"눌렀는데 반응 없음" 은 고장과 구별되지 않는다.** `navigateActive` 의 침묵 경로를 없앴다 —
  pane 이 없으면 새 탭으로라도 착지시킨다.
- **내 검증 조건이 실사용 조건이 아니면 세 번을 통과시킨다.** 데스크탑 앱은 부팅 경로가 다르다.
- **같은 브라우저로 여러 사례를 재면 탭 재사용이 판정을 오염시킨다** — 사례마다 새 컨텍스트.
- **Sequelize 속성명은 `createdAt`.** `created_at` 으로 심으면 무시돼 **0분으로 통과**할 뻔했다.
- **설계는 운영 실데이터가 정한다.** 청구가 월정액이라 시간은 덧붙이는 항목이 됐고,
  실제시간 기록률이 26%라 **기록률을 함께 띄우지 않으면 적게 청구하게 된다.**
- **DB 를 먼저 보면 진단이 바뀐다.** "2번 저장" 은 저장이 아니라 목록 합치기 문제였다.
